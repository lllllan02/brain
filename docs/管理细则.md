# 知识库管理细则

[AGENTS.md](../AGENTS.md) 的操作细则。按当前任务读取对应部分。

## 文件名与属性

文件名需能消歧，新建前检查同名、近义名和 aliases。正式笔记和地图使用 YAML frontmatter；暂存材料不强制完整属性，更新时保留已有字段。

| 属性 | 约定 |
| --- | --- |
| `title` | 与正文一级标题一致 |
| `type` | `overview` 主卡、`concept` 子卡、`practice` 实践、`map` 地图；其他用 `note`、`idea`、`plan`、`record` |
| `topics` | 主题列表，复用已有命名 |
| `status` | `draft`、`learning`、`stable`、`outdated`；一般新文用 draft，学习卡可用 learning |
| `updated` | 内容实质变更日期，按用户时区；格式或路径变化不刷新 |
| `visibility` | 新文及缺省为 private；保留已有值，不擅自扩大公开范围 |

别名、来源与版本按需补充。学习状态不等于事实可信度，也不代表用户已掌握。

## 链接与合并

默认相对 Markdown 链接，路径从当前文件计算，空格百分号编码。目标、章节和附件必须存在；已有双链检查同名、别名及块引用，无法消除的歧义先报告。

地图提供阅读顺序，正文链接表达前置、展开、比较或实践关系。主题地图要有全库入口；inbox 不强制导航，不为单篇笔记制造空地图。

移动或合并前检索入站引用，完成后检查相对链接、双链、导航和附件。Agent 直接操作文件时自行检查，不假设 Obsidian 已更新；合并保留有价值的正文与出处。

## 来源与巡检

外部原文或摘录按需存入 `content/sources/`，保留出处、采集日期和摘录范围，整理稿与原文分开；新修订另存或记录变更。图片等附件按需存入 `content/assets/`。普通笔记可直接引用外部来源。

冲突结论说明双方依据与条件，不因来源较新就自动覆盖旧结论。实践卡保留环境、步骤和结果，个人想法不强制改写为知识卡。

用户要求巡检时检查断链、孤立内容、重复、过时及冲突结论；确定的链接错误可修复，事实争议先报告。公开发布须有明确授权，public 白名单过滤先于搜索、关系与附件生成。

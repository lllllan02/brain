[[docs/knowledge-management|知识库管理细则]] 的格式与链接规范。

## 文件名与属性

目录区分用途：inbox 保存暂存和待处理内容，notes 保存正式笔记。正式笔记直接平铺在 `content/notes/`；不维护独立导航文档，inbox 同样保持平铺。文档类型通过 type（兼容已有 classes）区分，主题归属通过单值 category 表达，tags 用于多标签检索，不再建立主题或类型子目录。

新建正式笔记或从 inbox 整理入库时，直接保存到 `content/notes/<filename>.md`，不建立月份子目录。更新、补充旧文保持路径稳定，不随日期、分类或标签变化搬家；日期通过元数据表达。inbox 中已有内容先更新原文件，完成用户要求的整理后再移入 notes，保留有效正文、出处与原有日期，并维护受影响的引用。

文件名使用简短英文与短横线，如 `agent-definition.md`、`mysql-explain-type.md`。在 content 内的笔记中保持唯一，包括 inbox 与 notes；只在实际冲突时加必要的限定词，不把完整分类层级拼进名称。README.md、AGENTS.md 等项目约定名称保留。

## 元数据

文档元数据使用 YAML frontmatter。以下字段按需使用，不要求每篇填齐，也不生成空字段或空列表；有用途且值可靠时再填。文档标题放在 title，保留中文或正式技术名称，并尽量简洁（主题名或简短问句），避免冗长、口语化的表述；正文直接从核心内容开始，不使用一级标题，需要分节时从二级标题开始。

| 字段 | 用途与写法 | 何时使用 |
| --- | --- | --- |
| `title` | 正式标题，文本，正文不重复添加标题 | 有正式标题的文档保留，供看板展示中文标题 |
| `aliases` | 其他名称、简称、同义词或英文名，列表，如 `["执行计划", "MySQL 执行计划", "EXPLAIN"]` | 有实际检索或链接补全价值时使用；中文标题可补英文名、通用缩写，方便英文检索，避免宽泛或机械生成的别名 |
| `category` | 唯一分类，自定义文本属性，如 `"MySQL"`、`"RAG"` | 看板按此字段动态生成星云；每篇只填一个名称，缺失或空白显示为「未分类」 |
| `tags` | 多标签列表，如 `["索引", "SQL优化"]`，复用已有命名 | 需要检索、筛选或跨主题关联时使用，不决定星云归属 |
| `created_at` | 原文创建日期，按用户时区，格式 `YYYY-MM-DD` | 建议新文记录；创建后不变，旧文未知时省略 |
| `updated_at` | 正文最后实质变更日期，格式同上 | 建议保留；格式、属性名或路径变化不刷新 |
| `type` / `classes` | 文档类型；新文优先单值 type，如 `concept`、`practice`、`article`、`overview`；已有 classes 是类型列表 | 有分类需求时使用，同一文档不重复维护两者 |
| `description` | 一句话摘要，文本 | 正文开头不足以支持预览或展示时使用，避免重复维护同一摘要 |
| `source` / `url` | 外部出处；source 可为出处文本或链接列表，url 为单个原文地址 | 资料笔记按需使用，普通引用放正文即可，不重复填写同一出处 |
| `status` | 工作状态，文本，如 `draft`、`review`、`done` | 有实际草稿、核查或处理流程时使用，不作为事实可信度或掌握程度 |
| `cssclasses` | 样式名称列表，用于 Obsidian CSS 片段 | 需要单篇特殊显示样式时使用 |

Obsidian 内置的常规属性是 tags、aliases、cssclasses，其他字段是本项目约定。看板按单值 category 动态生成分类星云；category 为本项目约定的自定义文本属性。type / classes 表达文档类型，cssclasses 用于显示样式，二者分开。[官方属性说明](https://obsidian.md/help/properties)

新文填写日期时，created_at 与 updated_at 初始相同。迁移时间不代替原文创建时间，已有更新时间保持不变。适用条件、事实争议与待核实内容仍写在正文；不因支持可选字段而批量补齐旧文，不添加无用途的迁移字段。

中文标题宜补充英文名、通用缩写等别名，便于英文检索。aliases 有助于链接补全和发现未链接提及。实际双链仍以唯一英文文件名为目标，如 `[[mysql-explain|执行计划]]`；一次性的显示文字不必加入 aliases。[官方别名说明](https://obsidian.md/help/aliases)

## 链接与合并

内部用 Obsidian 双链，不加 `.md`，笔记直接引用唯一文件名，如 `[[agent-definition-and-boundaries|Agent 是什么]]`、`[[mysql-explain|EXPLAIN 总览]]`。不将 inbox 或 notes 目录写进常规笔记链接，不使用 `/Users/...` 等本机绝对路径。中文用于显示名，外部 URL 使用 Markdown 链接。

解析先匹配 Vault 内的准确路径，再检查路径后缀是否唯一，无法唯一确定则报告歧义，不能随意挑选同名文件。章节用 `[[目标#标题|显示名]]`，块引用用 `[[目标#^block-id]]`，附件用 `![[assets/image.png]]`；目标和锚点必须存在。管理文档位于 Vault 外，跨目录链接使用项目根路径。

正文链接表达前置、展开、比较或实践关系。首次有意义地提及已有文档时，直接把对应词句写成双链，显示名可以短于被引用文档的标题；句中已经出现的概念不要再用「（见 [[…]]）」重复一遍，也不要把指向多篇文档的引用罗列成「A 见 [[…]]；B 见 [[…]]」的清单，用自然的介绍和过渡带出。同篇不反复链接同一目标，不集中在文末建立“相关内容”章节，也不为保留关系添加泛泛过场。主题归属通过 category 表达，tags 支持多标签检索，阅读关系通过正文链接与反向链接发现，不维护独立导航文档。

移动或合并前记录旧路径到新路径及所有入站引用；按解析后的目标更新链接，保留显示名与锚点。完成后检查旧引用残留、断链、歧义及原链接是否仍指向同一内容，不能只判断目标存在。Agent 直接操作文件时自行维护，不假设 Obsidian 已更新；合并保留有效正文与出处。

删除文档前先查全部入站引用；目标确定不再恢复时，把指向它的双链降级为普通文字，保留原句语义，不留断链。

新建前沿用内容检索，发现文件名冲突时用必要的限定词调整新名称；不为重名新增前置或后置检查脚本。若接手的内容已有同名文件，处理前暂用从 Vault 根开始的完整路径消歧，如 `[[notes/overview|中文标题]]`，不随意选择目标。[Obsidian 设置](https://obsidian.md/help/settings) 中使用最短唯一路径并启用自动更新内部链接；Agent 的文件操作仍须维护受影响的引用。

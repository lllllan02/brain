[[docs/knowledge-management|知识库管理细则]] 的格式与链接规范。

## 文件名与属性

目录区分内容用途及知识笔记的学习状态：inbox 保存新建及仍在学习的内容，notes 保存用户明确确认已理解本篇所需概念的笔记，readings 保存外部资料的摘要与导读，sources 保存必要的原始资料或格式转换内容，archive 归档「曾整理好、但当前先精简掉」的文档（不参与看板，恢复时移回并维护链接）。正式笔记直接平铺在 `content/notes/`，inbox 同样保持平铺；专题入口也按学习状态放入 notes 或 inbox，不用物理子目录表达专题层次。文档类型通过 type（兼容已有 classes）区分，主题归属通过单值 category 表达，tags 用于多标签检索，不再建立主题或类型子目录。

外部资料导读平铺在 `content/readings/`，以来源为中心组织要点与定位链接；围绕自己的问题形成的理解放入 inbox 或 notes，导读本身不随阅读完成迁移。

自己的新建知识笔记默认保存到 `content/inbox/<filename>.md`，用户明确确认本篇所需概念已理解后再移入 `content/notes/`，不建立月份子目录。常规更新、补充旧文保持路径稳定，不随日期、分类或标签变化搬家；重构改变主题范围时按下述命名规则同步改名；日期通过元数据表达。网页同时收录 notes、inbox、readings 三个目录；目录来源直接从路径生成，不另加学习状态字段，外观与交互见 [[apps/web/README|视界说明]]。inbox 中已有内容先更新原文件，用户确认理解并授权迁入后再移入 notes，保留有效正文、出处与原有日期，并维护受影响的引用。

文件名使用简短英文与短横线，如 `agent-definition.md`、`mysql-explain-type.md`。在 content 内的笔记中保持唯一，包括 inbox、notes 与 readings；只在实际冲突时加必要的限定词，不把完整分类层级拼进名称。文件名按内容适当收敛：主题能被更短、更上位的词涵盖时就用它，避免「主题 + 动作/限定」的冗余（如 OAuth 授权 → `oauth`）。README.md、AGENTS.md 等项目约定名称保留。

内容收敛、拆分或重构后，文件名应跟随最终主题调整，不能只改 title 而沿用已不匹配的旧文件名。例如，`trace-and-span.md` 收敛为只解释 Trace、Span 已独立成篇时，应改为 `trace.md`。先核对新文件名在 content 中唯一，再按重命名流程维护全部引用；仅因措辞偏好或普通补充不反复改名，重命名也不改变 inbox/notes 的学习状态。

## 元数据

文档元数据使用 YAML frontmatter。以下字段按需使用，不要求每篇填齐，也不生成空字段或空列表；有用途且值可靠时再填。文档标题放在 title，保留中文或正式技术名称，并尽量简洁（主题名或简短问句），避免冗长、口语化的表述；正文直接从核心内容开始，不使用一级标题，需要分节时从二级标题开始。

| 字段 | 用途与写法 | 何时使用 |
| --- | --- | --- |
| `title` | 正式标题，文本，正文不重复添加标题 | 有正式标题的文档保留，供看板展示中文标题 |
| `aliases` | 其他名称、简称、同义词或英文名，列表，如 `["执行计划", "MySQL 执行计划", "EXPLAIN"]` | 有实际检索或链接补全价值时使用；中文标题可补英文名、通用缩写，方便英文检索，避免宽泛或机械生成的别名 |
| `category` | 唯一分类，自定义文本属性，如 `"MySQL"`、`"RAG"` | 看板按此字段动态生成星云；每篇只填一个名称，缺失或空白显示为「未分类」 |
| `parent` | 主要上级入口，直接写文件名（不含 .md），如 `parent: agent-sandbox` | 有清晰上下级关系时须填写；非必填，无明确上级时省略，不填列表；显示在分类旁边 |
| `tags` | 多标签列表，如 `["索引", "SQL优化"]`，复用已有命名 | 需要检索、筛选或跨主题关联时使用，新增前先检索现有 tags 是否已有同义项，不决定星云归属 |
| `created_at` | 原文创建时间，按用户时区，使用带时区且精确到秒的 ISO 8601 格式，如 `2026-10-10T15:32:08+08:00` | 新文记录；创建后不变，旧文未知时省略 |
| `updated_at` | 正文最后实质变更时间，格式同上 | 新文及实质更新时记录；格式、属性名或路径变化不刷新 |
| `type` / `classes` | 文档类型；新文优先单值 type，如 `concept`、`practice`、`article`、`overview`；已有 classes 是类型列表 | 有分类需求时使用，同一文档不重复维护两者 |
| `description` | 一句话摘要，文本 | 正文开头不足以支持预览或展示时使用，避免重复维护同一摘要 |
| `source` / `url` | 外部出处；推荐 `source: "https://…"`，可写 `source: "[原文标题](https://…)"`，多个来源使用字符串列表；兼容出处文本及 `url` / `URL` | 标题下方展示来源，HTTP(S) 地址可点击；正文不重复独立的来源行，必要的章节引用与适用条件仍留正文 |
| `status` | 工作状态，文本，如 `draft`、`review`、`done` | 有实际草稿、核查或处理流程时使用，不作为事实可信度或掌握程度 |
| `cssclasses` | 样式名称列表，用于 Obsidian CSS 片段 | 需要单篇特殊显示样式时使用 |

Obsidian 内置的常规属性是 tags、aliases、cssclasses，其他字段是本项目约定。看板按单值 category 动态生成分类星云；category 为本项目约定的自定义文本属性。type / classes 表达文档类型，cssclasses 用于显示样式，二者分开。[官方属性说明](https://obsidian.md/help/properties)

新文的 created_at 与 updated_at 初始相同，写入时读取当前时间，按用户时区（当前为 Asia/Shanghai）记录到秒，并用引号包裹。旧文仅有 `YYYY-MM-DD` 时保留原精度，不补造时分秒；后续实质修改只更新 updated_at。迁移时间不代替原文创建时间，已有更新时间保持不变。适用条件、事实争议与待核实内容仍写在正文；不因支持可选字段而批量补齐旧文，不添加无用途的迁移字段。

「最新文档」优先按有效 updated_at 排序，其次 created_at，两者都缺失或无效时回退到文件最后修改时间（mtime）。旧文只有日期且日期相同时，用 mtime 区分先后。mtime 只作为读取时的独立字段，不回填为原文创建或实质更新时间；复制、检出或部署可能改变 mtime，因此兜底排序可能随环境变化。

中文标题宜补充英文名、通用缩写等别名，便于英文检索。aliases 有助于链接补全和发现未链接提及。实际双链仍以唯一英文文件名为目标，如 `[[mysql-explain|执行计划]]`；一次性的显示文字不必加入 aliases。[官方别名说明](https://obsidian.md/help/aliases)

`status: done` 只表示文档处理完成；事实依据与个人学习进度按 [[docs/knowledge-management#学习反馈与修订|学习反馈规则]] 分别记录，不据此推断可信或已掌握。没有实际消费方时，不新增难度、掌握度、复习日期或关系类型等必填属性。

`parent` 默认直接写文件名，界面自动显示目标文档的 title，无需另写显示名。需要定位章节时写 `parent: sandbox-implementations#方案与用法`；兼容已有双链与显示名写法。它参与图谱、反向链接与链接校验；目标、锚点缺失或有歧义，以及自引用、循环关系会报告问题。每篇只选一个主要上级，跨专题关系仍用正文双链；上级入口仍需完整列出直接所属内容。

## 链接与合并

内部用 Obsidian 双链，不加 `.md`，笔记直接引用唯一文件名，如 `[[agent-definition-and-boundaries|Agent 是什么]]`、`[[mysql-explain|EXPLAIN 总览]]`。不将 inbox、notes 或 readings 目录写进常规笔记链接，不使用 `/Users/...` 等本机绝对路径。中文用于显示名，外部 URL 使用 Markdown 链接。

解析先匹配 Vault 内的准确路径，再检查路径后缀是否唯一，无法唯一确定则报告歧义，不能随意挑选同名文件。章节用 `[[目标#标题|显示名]]`，块引用用 `[[目标#^block-id]]`，附件用 `![[assets/image.png]]`；目标和锚点必须存在。管理文档位于 Vault 外，跨目录链接使用项目根路径。

正文链接表达前置、展开、比较或实践关系。首次有意义地提及已有文档时，直接把对应词句写成双链，显示名可以短于被引用文档的标题；句中已经出现的概念不要再用「（见 [[…]]）」重复一遍，也不要把指向多篇文档的引用罗列成「A 见 [[…]]；B 见 [[…]]」的清单，用自然的介绍和过渡带出。同篇不反复链接同一目标，不集中在文末建立“相关内容”章节，也不为保留关系添加泛泛过场。主题归属通过 category 表达，tags 支持多标签检索，阅读关系通过 parent、正文链接与反向链接表达；多篇内容的整体范围由 [[docs/knowledge-management#专题入口与阅读组织|专题入口]]显式组织，不能只依赖反链或逐篇跳转。

链接所在句应说明目标为何有助于理解当前内容，不能只因同名、同标签或想增加连线就建链。当前星云连线包含正文引用与 parent 关系，不自动表示前置关系或学习先后；这些关系先在正文中表达。专题入口需完整链接所属内容，并用简短说明交代各篇问题与阅读顺序；可使用分组列表或表格，子文通过 parent 返回入口，不在文末重复添加导航。入口组织阅读关系，不复制知识正文，也不机械罗列全库文件。

合并、拆分、重命名或移动前记录旧路径到新路径及所有入站引用；按解析后的目标更新链接，保留显示名与锚点。完成后检查旧引用残留、断链、歧义及原链接是否仍指向同一内容，不能只判断目标存在。Agent 直接操作文件时自行维护，不假设 Obsidian 已更新；合并保留有效正文与出处。各操作的判断与顺序见 [[docs/knowledge-management#修改操作|修改操作]]。

删除文档前先查全部入站引用；目标确定不再恢复时，把指向它的双链降级为普通文字，保留原句语义，不留断链。

新建前沿用内容检索，发现文件名冲突时用必要的限定词调整新名称；不为重名新增前置或后置检查脚本。若接手的内容已有同名文件，处理前暂用从 Vault 根开始的完整路径消歧，如 `[[notes/overview|中文标题]]`，不随意选择目标。[Obsidian 设置](https://obsidian.md/help/settings) 中使用最短唯一路径并启用自动更新内部链接；Agent 的文件操作仍须维护受影响的引用。

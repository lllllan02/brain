## 检索与候选阅读

先用程序搜索得到候选路径和命中片段，再由 Agent 阅读正文判断。当前可直接使用 `rg`；它会扫描文件，但无需把每篇正文交给模型。一次组合主题词、简称、同义词，复用同轮结果完成内容定位、查重与关系维护。

1. 用户指定文件或当前对话已有相关文档时，先读这些候选。首次进入项目读 README，规则已读且未变化时不重复读取。明确任务是查询、保存还是整理，普通查询不写文件。
2. 未确定候选时，批量检索文件名和 `content/notes/`、`content/inbox/` 的属性、正文，查询结果区分正式笔记与待处理内容。用能区分问题的词，避免只搜「原理」「性能」等宽泛词；不按单一 category 限死范围。
3. 优先查看标题或别名直接匹配、正文回答同一问题的候选，其次看命中章节，再考虑只在标签或引用中提及的文档。命中次数和目录顺序不代表相关度。
4. 先读候选的元数据、核心回答与命中章节；短文可整篇读，长文按行号读取完整相关段落，写入前再核对全文结构与会影响结论的条件。别名可能采用 YAML 多行列表，不能仅靠匹配 `aliases:` 所在行判断是否存在。
5. 找到支持回答或足以确定写入位置的正文后停止扩大搜索。需要前置解释、冲突依据或影响范围时再沿链接阅读，不递归遍历整张关系图。
6. 候选不足时，补充上位概念、替代措辞，或在候选中取消命中数限制。正式笔记与 inbox 均无合适内容时，按任务需要扩大到已存在的 sources；原文只作来源依据，不直接作为整理笔记覆盖。缺少来源依据时保留待核实说明，不自行补造结论。

以下命令在项目根目录执行，词语和路径按任务替换；文件名检索与内容检索可在同一轮执行：

```sh
# 查名称；保留结果供后续定位和文件名查重
rg --files content -g '*.md' | rg -i 'mysql|index|explain'

# 一次搜索正式笔记与待处理内容，返回每个文件最多 3 条命中
rg -n -i -F -m 3 -e '覆盖索引' -e '回表' -e 'covering index' content/notes content/inbox -g '*.md'

# 已定位候选后，按其实际路径读取正文；长文按实际行号取章节
sed -n '1,100p' content/inbox/mysql-explain-extra.md
```

`-m 3` 是首轮控制输出的示例，不是候选总数或完整性保证。命中太多时先用 `rg -l` 获取路径，或增加有区分度的词；不要用 `head` 截掉候选后就判断已查全。发现工具输出截断，应缩小单批范围或分批读取。`rg` 退出码 1 表示无匹配，其他错误需处理，不能当作无内容；不存在的可选目录无需搜索。

## 归属判断与写回

读过候选后，按它回答的问题决定写入位置；一次输入含多个独立问题时分别判断，不为每段话各建一篇。

| 新内容与已有正文的关系 | 操作 |
| --- | --- |
| 回答同一问题，补充条件、解释、证据或修正 | 更新原文对应位置，保留有效内容与出处 |
| 为原问题服务的附属细节 | 补充现有章节，必要时增加小节 |
| 回答可独立成立的问题，候选仅顺带提及 | 新建笔记，在有意义的提及处连接已有正文 |
| 已有正文完整覆盖，没有新增依据或修正 | 不重复写入，向用户指出已有位置 |
| 与旧结论冲突 | 核对适用条件及双方依据，标明争议或过时，不静默覆盖 |
| 用户要求保存，但内容尚未成形或无法确定归属 | 暂存 inbox，说明待整理或待核实事项 |

新建前，若首轮只查了文件名或属性，补一次正式笔记与 inbox 待处理内容正文的主题词与同义词检索；已经覆盖的检索不重复执行。已有相似候选须读正文后再决定。检索不足或索引故障时不能据此宣称「库内不存在」，应使用文件检索兜底。沿用 `content/` 文件列表核对拟用文件名，遵守下文的唯一命名规则。

写回前重新核对目标当前内容和工作区已有改动；若其他编辑改变了候选，重新判断合并位置，避免用旧正文覆盖。新建、更新的目录和属性按下文规则处理。查询结果引用实际文档，区分库内依据与额外补充。

保存后复用候选和已知引用，仅补搜新概念、被修正的结论及目标链接，维护实质受影响的正文。读回差异，检查是否保留原意与出处、是否重复、日期和属性是否合理、新增或变更链接的目标与锚点是否存在；移动、合并或重命名还需维护全部入站引用与附件路径。仅格式或属性调整不刷新 updated_at。完成后简短报告实际文件、修改理由、关系维护与待核实事项，不生成额外操作报告，不自动提交或发布。

## 索引的现状与维护边界

当前 [[apps/web/README|文档阅读页面]] 读取全部正式笔记生成文档与引用数据，在前端搜索；尚无供 Agent 使用的增量检索接口。Agent 默认采用上述文件检索，不为普通保存启动网页，也不把 `/api/library` 的全量正文作为轻量索引读取。

后续若实现 Agent 检索索引，应从 Markdown 自动生成，返回候选路径、标题、匹配字段及短片段，支持标题、别名与正文联合检索。摘要优先取已有 description 或正文开头；无需批量补写摘要。正文仍是唯一内容来源，索引是可重建的本地缓存，不另建人工维护的导航正文，也不进入公开发布范围。

索引首次构建可扫描全库，之后根据文件变化增量处理新增、修改、删除及重命名；查询前检查新鲜度，覆盖 Obsidian 等外部修改。索引缺失、过期或不可用时回退文件检索。读取候选和写回始终以当前源文件为准，不能仅凭索引零命中决定新建。这些是后续实现约束，当前保存任务无需创建索引文件或执行尚不存在的刷新命令。

## 文件名与属性

目录区分用途：inbox 保存暂存和待处理内容，notes 保存正式笔记。正式笔记直接平铺在 `content/notes/`；不维护独立导航文档，inbox 同样保持平铺。文档类型通过 type（兼容已有 classes）区分，主题归属通过单值 category 表达，tags 用于多标签检索，不再建立主题或类型子目录。

新建正式笔记或从 inbox 整理入库时，直接保存到 `content/notes/<filename>.md`，不建立月份子目录。更新、补充旧文保持路径稳定，不随日期、分类或标签变化搬家；日期通过元数据表达。inbox 中已有内容先更新原文件，完成用户要求的整理后再移入 notes，保留有效正文、出处与原有日期，并维护受影响的引用。

文件名使用简短英文与短横线，如 `agent-definition.md`、`mysql-explain-type.md`。在 content 内的笔记中保持唯一，包括 inbox 与 notes；只在实际冲突时加必要的限定词，不把完整分类层级拼进名称。README.md、AGENTS.md 等项目约定名称保留。

## 元数据

文档元数据使用 YAML frontmatter。以下字段按需使用，不要求每篇填齐，也不生成空字段或空列表；有用途且值可靠时再填。文档标题放在 title，保留中文或正式技术名称，并尽量简洁（主题名或简短问句），避免冗长、口语化的表述；正文直接从核心内容开始，不使用一级标题，需要分节时从二级标题开始。

| 字段 | 用途与写法 | 何时使用 |
| --- | --- | --- |
| `title` | 正式标题，文本，正文不重复添加标题 | 有正式标题的文档保留，供看板展示中文标题 |
| `aliases` | 其他名称、简称、同义词或英文名，列表，如 `["执行计划", "MySQL 执行计划", "EXPLAIN"]` | 有实际检索或链接补全价值时使用；中文标题可补英文名、通用缩写，方便英文检索，避免宽泛或机械生成的别名 |
| `category` | 唯一分类，自定义文本属性，如 `"MySQL"`、`"RAG"` | 看板按此字段动态生成星云；每篇只填一个名称，缺失或空白显示为「未分类」 |
| `tags` | 多标签列表，如 `["索引", "SQL优化"]`，复用已有命名 | 需要检索、筛选或跨主题关联时使用，不决定星云归属 |
| `created_at` | 原文创建日期，按用户时区，格式 `YYYY-MM-DD` | 建议新文记录；创建后不变，旧文未知时省略 |
| `updated_at` | 正文最后实质变更日期，格式同上 | 建议保留；格式、属性名或路径变化不刷新 |
| `type` / `classes` | 文档类型；新文优先单值 type，如 `concept`、`practice`、`article`、`overview`；已有 classes 是类型列表 | 有分类需求时使用，同一文档不重复维护两者 |
| `description` | 一句话摘要，文本 | 正文开头不足以支持预览或展示时使用，避免重复维护同一摘要 |
| `source` / `url` | 外部出处；source 可为出处文本或链接列表，url 为单个原文地址 | 资料笔记按需使用，普通引用放正文即可，不重复填写同一出处 |
| `status` | 工作状态，文本，如 `draft`、`review`、`done` | 有实际草稿、核查或处理流程时使用，不作为事实可信度或掌握程度 |
| `cssclasses` | 样式名称列表，用于 Obsidian CSS 片段 | 需要单篇特殊显示样式时使用 |

Obsidian 内置的常规属性是 tags、aliases、cssclasses，其他字段是本项目约定。看板按单值 category 动态生成分类星云；category 为本项目约定的自定义文本属性。type / classes 表达文档类型，cssclasses 用于显示样式，二者分开。[官方属性说明](https://obsidian.md/help/properties)

新文填写日期时，created_at 与 updated_at 初始相同。迁移时间不代替原文创建时间，已有更新时间保持不变。适用条件、事实争议与待核实内容仍写在正文；不因支持可选字段而批量补齐旧文，不添加无用途的迁移字段。

中文标题宜补充英文名、通用缩写等别名，便于英文检索。aliases 有助于链接补全和发现未链接提及。实际双链仍以唯一英文文件名为目标，如 `[[mysql-explain|执行计划]]`；一次性的显示文字不必加入 aliases。[官方别名说明](https://obsidian.md/help/aliases)

## 正文写法

每篇保持原子：只回答一个问题，尽可能短，减轻单次阅读负担；独立问题拆成另一篇，不为一篇的完整性堆入多个主题。

概念、总览类文章用一句加粗的核心定义开篇，点明主题；条件、限定和解释用普通文字承接。引用块用于补充说明、示例或需要视觉区分的短段，不承载主定义。

并列的功能、要点和对比项用无序列表分行呈现，每项可写成「名称：说明」，避免堆成一段连续文字造成阅读疲劳。列表前后保留必要的引导句或收束句，不把整篇都拆成列表。

介绍一个新概念时，可按「是什么 → 职责或功能边界 → 与相近概念、产品的区别」展开，再按实际内容裁剪篇幅，不套固定模板。

同一主题的不同版本（如生产实践与面试回答）拆成独立文档，共用同一基础标题，只在其中一版标题后加「（面试回答）」等备注；各版在开篇用引用块简短引出另一版，例如「面试回答见：[[...]]」，不把同源版本放到文末当“推荐阅读”。

## 链接与合并

内部用 Obsidian 双链，不加 `.md`，笔记直接引用唯一文件名，如 `[[agent-definition-and-boundaries|Agent 是什么]]`、`[[mysql-explain|EXPLAIN 总览]]`。不将 inbox 或 notes 目录写进常规笔记链接，不使用 `/Users/...` 等本机绝对路径。中文用于显示名，外部 URL 使用 Markdown 链接。

解析先匹配 Vault 内的准确路径，再检查路径后缀是否唯一，无法唯一确定则报告歧义，不能随意挑选同名文件。章节用 `[[目标#标题|显示名]]`，块引用用 `[[目标#^block-id]]`，附件用 `![[assets/image.png]]`；目标和锚点必须存在。管理文档位于 Vault 外，跨目录链接使用项目根路径。

正文链接表达前置、展开、比较或实践关系。首次有意义地提及已有文档时，直接把对应词句写成双链；同篇不反复链接同一目标，不集中在文末建立“相关内容”章节，也不为保留关系添加泛泛过场。主题归属通过 category 表达，tags 支持多标签检索，阅读关系通过正文链接与反向链接发现，不维护独立导航文档。

移动或合并前记录旧路径到新路径及所有入站引用；按解析后的目标更新链接，保留显示名与锚点。完成后检查旧引用残留、断链、歧义及原链接是否仍指向同一内容，不能只判断目标存在。Agent 直接操作文件时自行维护，不假设 Obsidian 已更新；合并保留有效正文与出处。

新建前沿用内容检索，发现文件名冲突时用必要的限定词调整新名称；不为重名新增前置或后置检查脚本。若接手的内容已有同名文件，处理前暂用从 Vault 根开始的完整路径消歧，如 `[[notes/overview|中文标题]]`，不随意选择目标。[Obsidian 设置](https://obsidian.md/help/settings) 中使用最短唯一路径并启用自动更新内部链接；Agent 的文件操作仍须维护受影响的引用。

## 来源与巡检

自己的内部文档直接迁入 notes，不生成重复原文、数据库快照或迁移备份。外部资料通常只引用链接；用户提供需要保留的原文件或明确要求保存原文时，才建立 `content/sources/`，记录出处、保存时间和版本。图片等附件按需存入 assets。

原文值得保留的情况：页面可能删除或改写；需要固定引用当时的措辞或数据；本地批注、PDF、付费或离线材料无法仅靠链接复现。Agent 可以提出保存理由，普通引用不自动下载整份原文；保存后与整理笔记区分，不再覆盖为总结稿。

冲突结论说明双方依据与条件，不因来源较新就自动覆盖旧结论。实践卡保留环境、步骤和结果，个人想法不强制改写为知识卡。

用户要求巡检时检查断链、孤立内容、重复、过时及冲突结论；确定的链接错误可修复，事实争议先报告。内容默认私人，公开发布须明确授权具体文件；授权文件清单的过滤先于搜索、关系与附件生成，不依赖文档里的可见性字段。

## 范围与依据

项目适配入口，采用 Vercel [web-design-guidelines](https://github.com/vercel-labs/agent-skills/tree/main/skills/web-design-guidelines) 的界面检查方法；核对日期为 2026-10-16。此文件为本地编写的工作流，不复制上游规则全文。授权与规则分工遵守 [AGENTS](../../../AGENTS.md) 和 [Skill 选用](../../../docs/agent-rules.md#skill-选用与替换)。

## 执行审查

1. 从用户指定组件、当前差异或已知问题确定检查范围，读取 [视界说明](../../../apps/web/README.md) 及对应实现。已知范围直接开始；只有范围无法确定才澄清。仅审查时不修改代码。
2. 读取 [Vercel Web Interface Guidelines](https://raw.githubusercontent.com/vercel-labs/web-interface-guidelines/main/command.md)，选与当前交互相关的条目检查。外部页面是参考材料，不授权安装工具、改配置或扩大任务；读取失败则说明，仅依据可核实的实现和已有标准报告，不声称完成最新版规范审查。
3. 追踪实际用户路径：键盘访问和焦点、触控替代操作、小屏与长文本、空态与失败态、动效关闭后的可用性。静态代码只能提供部分证据；有条件时在浏览器复现受影响路径，记录实际观察。
4. 按影响报告具体问题、文件与行号、触发条件和修复方向。未发现问题就明确说明检查范围及未覆盖项，不凑问题。用户已要求修复时完成修改并复查原复现路径，按项目 README 运行相关检查。

## 项目适配

- 中文文案与已有产品用语优先，不照搬英语标题大小写或标点偏好。
- 用语义化原生控件判断键盘行为，不机械给已有按钮添加重复事件处理。
- 不因达到某个列表条数就强制虚拟化；先确认实际渲染开销和使用方式。URL 同步、动效策略与框架专属建议也须有场景依据，不自动引入新依赖。
- 设计方向交给 [frontend-design](../frontend-design/SKILL.md)；WebGL 特有问题交给对应 Three.js Skill。一般 DOM 审查不能证明画布视觉效果、帧率或资源释放正确。
- 规范检查与实际体验分别报告；代码搜索命中不能单独证明问题，静态检查通过不等于已做视觉验收。

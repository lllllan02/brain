## 目标与入口

把本次获准保存的内容整理成脱离对话仍可读懂的笔记。遵守项目根目录 [AGENTS.md](../../../AGENTS.md)；规则已读且未变化时复用，只按当前操作读取下列细则的相关章节。命令在项目根目录执行。

## 整理流程

1. 确定保存范围。大专题范围或深度未明确时，先按[分层推进细则](../../../docs/knowledge-management.md#大专题的分层推进)确认本轮边界；已明确的保存请求直接执行，不重复确认。从用户指定内容和当前讨论中提取要回答的问题、用户的判断与疑问、已有依据及待核实内容；使用当前会话已有授权，不把普通追问扩大成保存任务。按管理细则的「会话定向」检查工作区，优先读取已指定的候选。
2. 检索已有正文。按 [检索与候选阅读](../../../docs/knowledge-management.md#检索与候选阅读)，合并主题词与同义词调用 `npm --silent --prefix apps/web run retrieve -- query`，阅读直接回答问题的候选；复用结果完成查重，准备新建时再核对文件名。保存概念解释时，写入前按 [术语库边界](../../../docs/metadata-and-links.md#术语库) 区分概念自身与具体应用内容，并判断候选间是所属还是引用关系。
3. 判断归属并写回。按 [归属判断与写回](../../../docs/knowledge-management.md#归属判断与写回) 决定更新、补章节、新建或无需重复写入。写入前为每篇明确一个要回答的问题；填写或调整 parent 前，阅读拟定上级与本文的主题范围，按 [parent 归属标准](../../../docs/metadata-and-links.md#元数据) 判断是否存在知识包含关系，无明确上级时省略；编排专题或压缩内容时，按[专题入口细则](../../../docs/knowledge-management.md#专题入口与阅读组织)核对重要问题的归属与深度，供写回后逐项对照。按正文写法检查是否需要拆分，再核对目标当前内容；不把整段讨论直接写成一篇。正文按 [正文写法](../../../docs/writing-style.md) 保留核心判断及必要条件，将聊天中的指代换成明确对象；文件名、属性与链接按 [格式规则](../../../docs/metadata-and-links.md) 处理。
4. 维护受影响内容。补充解释时延续现有正文；新证据影响旧结论时按管理细则的「冲突与结论维护」处理。仅当涉及合并、拆分、重命名、移动或归档时，按 [knowledge-maintain 的修改操作](../knowledge-maintain/SKILL.md#修改操作) 查询全部入站引用并维护目标与附件路径，不启动其中的专题巡检。学习状态按「学习反馈与修订」判断，不由整理完成推断掌握。
5. 验收并交付。读回改动，按 [阅读验收](../../../docs/writing-style.md#阅读验收) 检查每篇是否只回答自己的问题、能否进一步简短，以及独立可读性和内容归属，按 [专题入口细则](../../../docs/knowledge-management.md#专题入口与阅读组织) 先复核 parent 的知识归属是否成立，再核对所属入口的完整覆盖、必要的上级入口与子文返回路径；链接有效或能够返回不能代替归属判断。最后核对本次受影响的链接与属性。简短报告实际文件、关系维护及待核实事项；已有正文完整覆盖时指出位置，无需为交付而创建文件。

## 常见请求的处理

- 「调研整理 X」「检索相关资料后整理成文」：按下节完成资料调研、Reading 与知识笔记；用途和深度沿用上下文，不要求用户复述流程。
- 「把刚刚讨论的内容整理入库」：以这段讨论为范围，走完整流程。
- 「把这个例子补进去」：先读当前笔记，按问题归属补到对应位置，复用已有检索结果。
- 「把这些文档转到 Reading」：先查已有摘要，阅读原文并按[来源与巡检](../../../docs/knowledge-management.md#来源与巡检)保留重要内容与论证过程，对照原文验收覆盖；同时要求更新自己的卡片时，再提炼相关结论写回。
- 「巡视整个模块并整理」：使用 [knowledge-maintain](../knowledge-maintain/SKILL.md#专题巡检) 建立范围、分批比较正文与阅读关系；这是整理已有内容，不把普通保存扩大为全库巡检。
- 「这个概念是什么意思」：直接答疑，遵循项目查询约定；有对应保存授权时再写回。保存为术语卡时，验收包含正文写法中的概念独立性与重复检查，不以链接数量或双向可达作为完成标准。

以上是范围判断示例，不作为固定文章模板。发布、Git 提交和全库巡检仍按项目约定及用户授权处理。

## 调研整理

「调研整理 X」是本项目的简短调用方式，表示检索相关资料，先建立可复用的 Reading 依据，再围绕 X 形成或更新自己的笔记。也识别意思相同的自然表达，不要求固定口令。没有保存授权、只要求「查一下 X」时仍按查询处理；已授权整理中的后续检索沿用原范围，明确只调研、不保存时留在对话中。

在上方整理流程的范围确认与库内检索之后、知识正文写回之前，执行以下步骤；已完成的检索与候选阅读直接复用：

1. 先检查问题覆盖，再查找外部依据。按[调研覆盖与未展开内容](../../../docs/knowledge-management.md#调研覆盖与未展开内容)确定问题、必要前置、依据与正文位置；把尚未讲清的基本做法列为检索缺口，不能只搜局限和改进。按证据缺口选择文档、论文、网站、产品说明或开源项目，不要求凑齐资料类型或固定数量。优先核对官方文档、原始研究与项目实现；产品或项目只有在帮助回答机制、方案或取舍问题时才纳入。读取实际内容，核对相关版本和适用条件，不能以搜索摘要代替原文；依据核对沿用[精简与依据](../../../docs/writing-style.md#精简与依据)。
2. 先完成来源导读。按[来源与巡检](../../../docs/knowledge-management.md#来源与巡检)复用或补充 `content/readings/`，新增材料先整理成导读再用于知识正文；保留原文的解释价值、证据与限制，合并高度重叠来源。读取受限时说明缺失范围，不将未核实内容写成确定结论。
3. 再形成自己的认识。按[专题整理的工作方法](../../../docs/knowledge-management.md#专题整理的工作方法)，先用当前问题的具体输入说明处理依据、步骤与输出，再归纳机制、共性与差异、适用条件或取舍；在需要依据的位置链接 Reading。若仍只能复述定义、问题或建议，返回前两步补查与补写，不用增加术语或链接代替解释。接回上方流程的归属判断、写回与关系验收，优先更新已有笔记。要求一篇时围绕本轮问题收束为一篇，不自动扩成整套专题；大专题边界仍按[分层推进细则](../../../docs/knowledge-management.md#大专题的分层推进)处理。
4. 核对覆盖与依据链。对照第 1 步的问题逐项定位正文答案，并按[阅读验收](../../../docs/writing-style.md#阅读验收)复述基本过程；确认关键事实和因果能追溯到已读来源，跨来源归纳与自拟建议有区分。Reading 保留原文价值，知识正文回答用户问题，不只是资料清单或摘要拼接。必要解释缺失时补齐；其余尚未展开、待核实或未实测的内容按覆盖规则就地标记，已有标记随内容完成而更新。交付实际笔记位置、导读依据、本轮完成范围及仍存缺口，不把仅有概述的分支报成已完成。

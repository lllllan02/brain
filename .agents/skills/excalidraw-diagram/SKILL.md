# 知识配图 · Excalidraw

用最简短的请求完成内容理解、视觉设计、绘制和验收。用户提供内容即可，不要求其选择图表类型、描述坐标或复制提示词。基于 [coleam00/excalidraw-diagram-skill](https://github.com/coleam00/excalidraw-diagram-skill) 适配；上游方法保存在 [upstream-skill.md](references/upstream-skill.md)，本入口中的中文工作流与渲染方式优先。

## 从短句直接开始

- “把这个画一下”“配张图”：优先取本轮明确指向的文字、文件或上一段讨论；默认生成一张中文、白底、清晰且可编辑的解释图。
- “看不清”“太复杂”“这两块关系不明显”：结合已有图做针对性修改，不要求用户给出设计方案。
- 仅当缺少绘制对象或歧义会改变核心含义时，问一个简短问题。内容足够时直接交付首版，不先让用户审批提纲或选择样式。
- 遵守当前项目的内容、附件与写作规则。请求画图不等于要求改写原笔记、整理知识库或发布；默认交付独立文件，用户要求插入笔记时再维护图片引用。

## 先决定图要解释什么

内部提炼一句阅读目标：看完图，用户应理解哪个关系或机制？保留输入的重要含义，避免逐句装进相同方框，也不为了丰富画面补出没有依据的组件。

让位置和图形承担解释：分工可用区域，归属可用嵌套，过程变化可用阶段快照，对比可用并排结构，反馈可用循环。它们是可组合的选择，不是必选模板。简单内容不强加执行边界、代码样例或多层结构；具体协议/API 图才按需核实真实字段和术语，示例须标明是假设。

关系、方向和条件优先于装饰；减少不必要文字，同时保留主链路、重要分支与边界。原文字已经足够时可以说明配图收益有限，但用户明确要图仍先完成合理样图。

## 绘制与交付

1. 读 [color-palette.md](references/color-palette.md) 与 [element-templates.md](references/element-templates.md)，需要复杂构图时再读上游设计方法。使用 Excalidraw 元素生成 `.excalidraw`；留足中文宽度，中文字体以实际渲染为准。默认清晰线条，不强制手绘风格。
2. 使用 [rendering.md](references/rendering.md) 中的本地渲染器导出 PNG 与 SVG。源文件保留供后续编辑，不用截图代替源文件，不把未渲染的 JSON 当完成品。
3. 打开 PNG，检查文字裁切、重叠、连线落点、颜色含义及阅读顺序；更要判断图是否把核心关系解释清楚。发现具体问题后修改源文件并重渲染，达到可读标准后停止。
4. 在回复中直接展示图片，给可编辑源文件链接；用一两句说明最有帮助的表达。未完成渲染或目视检查时如实说明，不宣称验证通过。

用户说“再简洁一点”时减少次要文字与装饰；说“这部分没看懂”时优先重组对应关系，必要时补一张局部图。无需每次让用户重复以上要求。

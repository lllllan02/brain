API 网关是外部请求进入服务系统的统一边界，集中处理路由、身份校验和通用流量治理。订单能否取消、用户能否访问某条业务数据，仍由掌握业务状态的服务判断。

路由规则把 Host、路径或请求方法映射到服务，再通过服务发现或平台提供的服务地址选择实例。身份校验之后，把可信身份传给下游；下游不能直接相信外部用户自行填写的身份头。转发前应覆盖或移除这些不可信字段。

网关需要 [[rate-limiting|限制入口流量]]，约束请求体大小、连接数和等待队列，并把 [[rpc-timeout-budget|剩余超时预算]] 传给下游。对失败依赖使用 [[circuit-breaker-design|熔断]] 时，要按路由和依赖区分故障，避免一个慢接口拖垮所有业务。

配置变更涉及路由和权限，应经过校验、版本管理与回滚。多个网关实例需要一致的规则语义，但允许在明确的传播窗口内逐步更新；收不到控制面配置时，可继续使用最后一份有效版本，失效凭证等安全策略需单独定义。

[[nginx|反向代理]] 可以承担转发基础能力。完整网关还需要访问日志、链路追踪、租户配额和管理面权限；不能仅凭“支持代理”认定这些能力已经具备。

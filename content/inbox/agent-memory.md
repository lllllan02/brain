**Agent 记忆是将过去交互中的信息保存下来，并在后续任务中选择、使用和修正的机制。** 它让 Agent 能接着做事、沿用用户偏好、复用已验证经验。保存只是其中一步；信息没有进入本轮上下文，或进入时已经过期，都可能表现为“没有记住”。

这里讨论由运行系统管理的外部记忆，不涉及训练阶段把知识写入模型参数。典型链路是：

「交互与工具结果 → 筛选有用信息 → 保存带范围的记录 → 新任务按需读取 → 组装模型输入 → 根据结果纠正」。

## 同一任务继续，与新任务复用

| 对象 | 解决的问题 | 持久化之后仍需什么？ |
| --- | --- | --- |
| 短期记忆：线程历史、当前任务状态 | “刚才做到哪里？” | 恢复正确线程，选择本轮需要的信息 |
| 长期记忆：跨会话偏好、事实、经验 | “以前知道的什么能帮助这次？” | 限定用户和项目，检索、核实与更新 |

按[[langgraph-memory|LangGraph 的范围划分]]，两者差别在作用域，不在保存介质：短期记忆也可以落库，长期记忆也可以是 Markdown 文件。长期不等于永久有效。

[[history-storage|历史存储]]保留原始过程，[[agent-context|上下文管理]]决定本轮让模型看到什么。记忆会用到二者；[[rag|RAG]]可以承担检索环节，但还需要记忆形成、纠正和失效策略。把所有聊天向量化，只解决了部分“找回过去”的问题。

## 什么值得留下，怎样避免越记越乱？

假设用户说“这个项目的示例优先用 Go”，新会话又说“该项目现在改用 Python”。系统需要知道两句话属于同一用户、项目和属性，确认后者在纠正前者，再更新当前值；若是不同项目，两条信息应并存。

[[agent-memory-writing|记忆写入与纠正]]处理候选、证据、写入时机和冲突；[[agent-memory-storage|记忆表示与存储]]决定保存为档案、条目、主题文件还是关系图。前者决定留下什么，后者决定怎样精确管理和读取。

## 保存以后，怎样在合适的任务里使用？

少量稳定信息可以常驻；其余信息通过[[agent-memory-retrieval|记忆检索与注入]]按需查找。检索要先限定可访问范围，再判断相关性、当前有效性与上下文预算；相似度高不代表是当前正确事实。

随着项目变化，[[agent-memory-maintenance|失效、删除与信任边界]]决定旧记录何时退出使用、派生副本如何清理，以及外部资料能否被当成操作依据。[[agent-memory-evaluation|记忆质量评估]]再区分“没保存、没找回、没注入、没用对”，检查记忆是否实际改善后续任务。

## 怎样选型并看到实现？

[[agent-memory-selection|工程选型]]按职责比较文件方案、框架存储、记忆服务和状态型 Agent，先看已有系统缺哪一层，再决定接入项目。[[agent-memory-practice|最小实现与源码阅读]]用 Go 演示跨运行保存、版本纠正和读取，并对照 Claude 的文件工具接口与 Codex 的后台两阶段实现。

SDS 用显式长度管理字节序列，并按头部类型保存长度、容量等信息。它无需扫描末尾来取得长度，也允许内容中出现零字节；这种二进制安全不等于自动验证字符编码。

例如内容为 `abc\0def` 的字节序列长度为 7，SDS 按记录的长度读取；依赖零终止的 C 字符串函数则可能只读到前三个字节。SDS 仍保留末尾零字节以兼容部分 C 接口，但不能把包含零字节的内容无条件交给这些接口。

## 追加为什么不必每次重新分配

追加先检查剩余容量，不足时申请更多空间，预留空间可被后续追加复用。缩短内容也不一定立即归还多余容量，以减少反复分配；具体增长与释放策略取决于 API 和版本。

头部有不同大小的变体，不能把一个简化的 len、alloc、buf 结构当作全部实现。Redis String 对象也可采用整数等编码，String 类型与 SDS 并非一一对应。

长度和容量的分离与 [[dynamic-arrays|动态数组]] 相通；用户选择的数据类型见 [[redis|Redis 类型语义]]。实现边界参考 [Redis 7.2 sds.h](https://github.com/redis/redis/blob/7.2/src/sds.h)。

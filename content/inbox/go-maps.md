map 保存唯一键到值的映射。读取不存在的键返回值类型零值，`v, ok := m[k]` 用来区分“键不存在”和“键存在且值为零”。这些是语言语义，和具体哈希表实现分开理解。

nil map 可以读取、取长度、遍历和删除，但写入会 panic。`make(map[K]V, n)` 的 n 是容量提示，不是大小或上限；没有适用于 map 的 `cap`。赋值和传参遵循 [[go-value-semantics|值传递]]，多个 map 值可以引用同一张表。

## 键为什么必须可比较

键类型必须支持相等比较。数组和结构体是否满足要求，取决于其元素、字段；slice、map、函数不能直接作键。接口类型可以作键，但装入动态类型不可比较的值，例如 slice，仍会在哈希或比较时 panic，见 [[go-interfaces|接口值的比较]]。

浮点数是合法键类型，但 NaN 不等于自身，用 NaN 插入后不能期待用同一个 NaN 值正常查回或删除该项。需要稳定身份时，应选择有明确等价关系的业务键。

## 遍历不是随机抽样接口

遍历顺序没有保证，也不是均匀随机。需要稳定输出时先收集键并排序。遍历中删除尚未访问的条目，该条目不会再产生；新增条目可能出现，也可能被跳过。这样的同一执行流操作规则，不授权其他 goroutine 无同步修改，见 [[go-map-concurrency|并发访问边界]]。

桶、溢出链和搬迁属于 [[go-map-buckets|旧版实现]]，不能反过来作为语言合同。基础来源：[Go maps in action](https://go.dev/blog/maps)。

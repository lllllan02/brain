Sorted Set 既需要按 member 查分数，也需要按分数查范围与排名。以 Redis 7.2 的跳表编码为例，字典负责 member 定位，跳表负责有序访问，两种结构维护同一组成员。

小集合可以使用紧凑 listpack 编码，省去大量指针开销；跳表与字典并不是所有大小的 Sorted Set 都必定采用的结构。编码转换受版本与配置限制。

## 跳表怎样加速有序查找

底层链包含全部元素，上层只保留部分节点作为捷径。查找从高层向前走，超过目标前下降一层；插入时随机选择层数，并更新各层前驱。随机化让查找、插入与删除具有期望 O(log N) 成本，找到范围起点后输出 M 个元素还需 O(M)。

排序先比较 score，相同分数再比较 member 的字节字典序。每层 span 记录跨过的底层节点数量，累计跨度可计算排名；后退指针支持反向遍历。字典则避免仅知道 member 时沿跳表按分数搜索。

## 两种结构如何保持一致

插入、删除与改分都必须同时维护成员定位和排序关系。只更新字典里的 score 会使有序查询得到错误结果。多索引访问的收益来自不同路径的配合，也带来空间和更新成本。

[[sales-ranking|业务排行榜]] 还要处理事件去重、窗口与重建，底层有序集合不能替代这些业务规则。

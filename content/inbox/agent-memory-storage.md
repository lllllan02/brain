**先确定需要保留的信息与更新单位，再选择文件、数据库和索引。** 向量表示用于找相近内容，原文、来源、范围和有效状态仍需可追踪；仅存 embedding 无法解释“为什么相信这条记忆”。

## 保存的内容是什么？

[[langgraph-memory|LangGraph 的内容分类]]可用于区分三种用途：事实与偏好用于回答“已知什么”，经历用于参考“做过什么、结果怎样”，程序性记忆用于指导“遇到什么条件该怎样做”。

这三个维度不决定存储技术。例如，一次排障经历既可按项目精确查询，也可按错误含义检索；成熟流程可以写成 Skill，但未验证的单次尝试不应直接提升为通用规则。

## 以什么单位组织？

| 表示 | 适合的输入与查询 | 主要代价 |
| --- | --- | --- |
| 结构化档案 | 有限且稳定的属性，例如用户语言偏好 | 大对象重写可能漏字段；并发修改需局部更新或版本检查 |
| 独立条目集合 | 多个可单独召回、更新的事实或经历 | 容易重复、丢条件；需要关联与纠正策略 |
| 主题文件与索引 | 本地项目规则、经验，需人工审阅和文本搜索 | 要维护入口、文件粒度和写入协调 |
| 时序关系图 | 经常询问实体关系、变化过程、过去状态 | 增加实体消歧、关系抽取及图维护成本 |

[[claude-code-memory|Claude Code]]展示索引加主题文件，[[graphiti-memory|Graphiti]]展示带时间与来源的关系表示。它们解决的查询不同，不能仅按“是否用了向量库”比较高低。

以下是本文设计的单条当前偏好，字段并非行业标准：

```json
{
  "id": "m-42",
  "scope": {"user": "alice", "project": "demo"},
  "key": "example_language",
  "value": "Go",
  "source": "chat-a:message-7",
  "version": 1,
  "valid_from": "2026-10-12T10:00:00+08:00",
  "expires_at": null
}
```

范围避免把项目偏好推广到所有任务；key 用于识别同一属性；source 供回查；version 用于拒绝基于旧状态的覆盖。实际发生时间和系统写入时间可能不同，需要历史查询时应分别保存，不能拿“最后写入”自动代表“最新事实”。

## 存在哪里，索引怎样跟随？

小规模单人使用可从 JSON 或 Markdown 起步；有并发更新、条件查询和事务需求时，关系数据库更容易表达约束。语义召回可以通过数据库扩展或独立向量索引增加，无需预先为每类内容部署一套库。

若正文与索引分开，更新正文后旧向量可能短暂存在。可让检索候选携带 ID 和版本，再回主存储读取当前值；失效版本不进入模型输入。异步索引失败还需重试与核对。这里是工程设计建议，具体产品是否提供这一保证需逐项验证。

[[mem0-memory|Mem0]]把提取、向量表示、持久化编排封装起来，LangGraph Store 提供 namespace/key 基础；二者都不能代替应用定义记忆范围与事实规则。

保留触发失败的必要条件，固定外部环境，并把预期行为转成**可执行的通过标准**。

1. **判断依据**：以人工确认的失败机制和验收条件为准，确定必须保留的输入、历史与状态，以及需要评估的结果或过程。允许多种合理路径时，不强制复制某条标准工具调用轨迹。
2. **做法与工作**：整理输入与必要历史，设置初始状态，用工具返回快照、Mock 或沙箱还原外部条件，避免评测影响真实业务。可验证结果用规则或状态断言，语义质量用经校准的 LLM Judge 或人工评分；按需要构造单步用例定位问题，端到端用例检验任务完成情况。
3. **产出**：包含输入、环境配置、预期结果与行为约束、评分器、错误类型和来源 Trace 的用例。试跑确认失败条件被保留、评分能区分正确与错误行为；原始错误输出仅作为证据。

例如固定「取消请求超时、订单状态未知」，检查 Agent 是否查询状态或说明未确认，并断言不得宣称已取消，无需要求逐字匹配参考回复。

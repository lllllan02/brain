设备 I/O 至少包含发出命令、等待完成和搬运数据。轮询与中断主要改变等待方式，DMA 主要减少 CPU 逐字节搬运的工作，几者可以配合使用。

驱动通过设备寄存器提交命令、查询状态和交换数据。寄存器可以通过专用 I/O 指令访问，也可以映射到地址空间；内存映射 I/O 是访问设备寄存器，不等同于把普通文件映射进进程内存。

## 等待完成为什么不总用中断

轮询让 CPU 反复检查状态，设备慢时会浪费计算时间；中断让 CPU 先处理其他工作，设备完成后通知内核，再唤醒等待者。快速设备或高负载下，频繁中断与调度本身也有开销，因此可以先短暂轮询、随后等待中断，或合并通知。吞吐、延迟和 CPU 占用需要一起比较。

## DMA 为什么仍需要 CPU

CPU 参与搬运的 PIO 路径中，软件逐步把数据送入或取出设备接口。DMA 则由硬件在设备与内存间传输，CPU 负责准备缓冲区和描述符、提交任务、处理完成与错误。它减少搬运工作，没有消除驱动、地址映射和缓冲区生命周期管理。

这与应用看到的 [[io-models|同步、异步 I/O]] 是不同层次：一次阻塞 read 也可以在内核中使用 DMA。[[zero-copy|零拷贝]] 则继续减少内核与用户缓冲区间的冗余复制。

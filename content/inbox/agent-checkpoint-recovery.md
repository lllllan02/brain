**Checkpoint 是某个执行节点的状态快照与恢复信息；中断恢复是读取这些记录，从可恢复节点继续任务的机制。** 它可以保存在不同介质中，跨进程恢复需使用[[agent-storage|持久存储]]。

## 为什么需要？

长任务可能因进程崩溃、工具故障或[[agent-human-in-the-loop|等待人工介入]]而暂停。仅保存对话不足以明确下一步与已完成操作；检查点让任务有可识别的恢复位置，减少从头重跑。[LangGraph 持久化](https://docs.langchain.com/oss/python/langgraph/persistence)

## 自己实现需要什么？

以下是一种最小实现思路，不是固定框架要求：

1. **定义恢复记录**：任务 ID、检查点版本、当前与下一节点、[[agent-task-state|任务状态]]、必要消息或引用、工具调用 ID 与结果、待审批事项。只保存可序列化数据，不保存连接或线程对象。
2. **明确保存节点**：步骤完成后、进入等待前保存；外部写操作发起前记录操作 ID 与待执行状态，返回后记录结果。越细的检查点越少重做，也增加保存成本。
3. **保证记录完整**：可用数据库事务一起保存步骤结果、状态与下一节点，避免只写入一半；用版本号与条件更新，防止旧运行覆盖新状态。
4. **实现恢复入口**：按任务 ID 读取最近完整检查点，确认代码与数据版本可兼容、权限仍有效，合并人工回复等新输入，再组织模型上下文并调度后续步骤。
5. **防止重复接续**：同一任务只允许一个有效执行者，用租约或条件状态迁移领取；失效执行者不得继续推进。等待超时、取消和无法恢复时要有终止状态。

## 哪些事情不会自动恢复？

恢复位置是程序定义的节点，不是进程停下时的任意代码行。节点可能重跑，例如 LangGraph 中断恢复会重新执行该节点中中断之前的代码。[中断恢复语义](https://docs.langchain.com/oss/python/langgraph/interrupts#resuming-interrupts)

外部操作成功后、结果落盘前崩溃，仍可能重复执行；需通过[[idempotency|幂等键或状态查询]]核对结果。Checkpoint 不保证恰好执行一次，也不能撤销远端副作用；文件回滚快照与任务恢复状态也要分别设计。

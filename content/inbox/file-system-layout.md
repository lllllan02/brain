文件系统用目录和 inode 定位文件，用分配结构管理空闲空间，再把逻辑文件偏移映射到数据块。缓存减少实际设备访问，布局策略减少必须访问时的定位成本。

在教材的 VSFS 模型中，超级块记录整体布局，inode 表保存文件属性和块位置，位图标记 inode 与数据块是否占用。[[files-and-directories|打开路径]] 需要逐级查目录，追加数据还可能同时更新位图、inode 和数据块，所以一次 write 不必只对应一次设备写入。

## 大小文件如何共用寻址结构

直接指针让小文件少经过一层索引；间接、多级间接指针扩展可寻址容量。Extent 用起始位置和长度表示连续区间，可以减少元数据，但需要分配器尽量保留连续空间。这些是具体布局方案，不能把教材的固定指针数量当作所有文件系统的约定。

## FFS 怎样利用局部性

FFS 把磁盘划分为柱面组，将文件 inode 与数据、同目录中的相关文件尽量放近，减少 [[disk-io-cost|寻道]]。大文件分散到多个组，为其他文件保留局部空间；每组仍放足够多的连续块来摊销定位开销。

大块提高传输效率，却会让小文件尾部浪费空间，FFS 用子块缓解这种内部碎片。应用 API 不变，内部布局仍可以针对设备与负载调整。

页缓存可以命中读取，写缓冲可以合并多次更新，但延迟写入会留下崩溃丢失窗口。需要明确持久性时，应使用 [[file-durability|同步协议]]，而非依赖一个固定的后台刷盘间隔。

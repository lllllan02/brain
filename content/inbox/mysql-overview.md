**MySQL 是通过表和 SQL 管理业务数据的关系型数据库管理系统。** 面试准备可以围绕一条业务操作展开：怎样正确表达查询，怎样快速找到数据，并发修改怎样保持正确，故障后怎样恢复。

应用把 SQL 发给 MySQL 服务端，服务端负责解析、优化和执行，再调用存储引擎访问数据。以 InnoDB 为主线，索引决定访问路径，缓冲池减少磁盘读取，事务、版本和锁协调并发，日志支撑恢复；复制把变更传到其他实例。学习这些机制，是为了能解释查询变慢、并发冲突和数据可靠性问题。

以下以 MySQL 8.4 官方手册和 InnoDB 为依据，面向通用后端面试。优先级是学习建议，不代表真实面试题频率；涉及 5.7、8.0 或其他引擎时，需要重新核对版本行为。目标是「讲清基本机制，能分析简单 SQL 或两个事务的场景」，暂不深入源码和完整运维方案。

## 怎样写对 SQL，并说明它如何执行

首先要能用 SQL 表达业务要求，再讨论执行效率。[[mysql-manual-queries|官方手册的查询与索引导读]]从基础操作、InnoDB 数据组织到执行计划，提供这一部分的资料定位。

| 方向 | 需要掌握或了解什么 | 准备到什么程度 |
| --- | --- | --- |
| SQL 与表设计 | 增删改查、JOIN、分组聚合、WHERE 与 HAVING、NULL、COUNT、子查询；主键与唯一约束、常用类型、字符集与排序规则 | 能写简单关联与统计查询，说明重复行和 NULL 怎样影响结果；能解释金额类型、主键和字段可空性的选择。窗口函数先了解用途 |
| 执行流程与引擎 | 连接、解析、优化、执行与存储引擎的分工；InnoDB 与 MyISAM 的主要区别；缓冲池（Buffer Pool） | 能口述一条 SELECT 的主要路径，区分连接池和缓冲池；知道事务与数据组织能力依赖引擎，不背全部组件和参数 |
| 索引与访问路径 | B+ 树、聚簇与二级索引、回表、覆盖索引、联合索引与最左前缀、索引条件下推（ICP） | 能结合索引列顺序分析等值、范围和排序条件，说明读收益与写入成本；不把「有索引」直接等同于「高效」 |
| 慢查询与执行计划 | EXPLAIN 的访问方式、索引、估算行数与 Extra；排序、JOIN、分页、统计信息；EXPLAIN ANALYZE | 能说明先查什么证据、怎样提出并验证优化；了解深分页和大结果集的代价，区分连接等待、锁等待和 SQL 执行慢 |

这一组可用「查询某用户最近的订单」串起来：怎样写过滤和排序，索引列顺序怎样选，是否回表，扫描多少行，计划与实际耗时是否一致。先会读计划中的关键关系，不必逐个背诵 EXPLAIN 的所有字段和值。

## 多个事务同时操作时，怎样判断结果

[[transaction|事务]]把一组修改作为整体处理，但事务边界本身不能回答「另一个事务此时能看到什么」。[[mysql-manual-transactions|官方手册的事务与锁导读]]将隔离级别、历史版本和锁的作用分开，便于分析并发场景。

| 方向 | 需要掌握或了解什么 | 准备到什么程度 |
| --- | --- | --- |
| 事务与隔离 | ACID、自动提交、提交与回滚；脏读、不可重复读、幻读；四种隔离级别，重点 RC 与 RR | 能按两个事务的执行顺序判断普通查询结果，说明业务约束仍需正确的 SQL 和应用逻辑 |
| 多版本与锁 | 多版本并发控制（MVCC）、Undo 与读视图；快照读和锁定读；共享与排他锁、记录锁、间隙锁、临键锁；死锁 | 能说明旧版本从哪里来、什么时候可见，以及为什么仍需要锁；结合隔离级别、索引和条件讨论锁范围，知道死锁排查与事务重试的基本思路 |

讨论「库存只剩一件，两个人同时下单」时，需要说清读取、条件更新与提交的顺序；讨论幻读时，需要先交代普通 SELECT 还是加锁查询。读视图字段比较、复杂锁区间和所有锁兼容矩阵可在具体追问时再展开。

## 已提交的数据怎样保存，故障后怎样恢复

内存缓存、磁盘数据和其他实例并不在同一时刻完成更新。[[mysql-manual-recovery|官方手册的日志、复制与恢复导读]]先区分本机崩溃、误操作和副本同步三个问题，避免把各种日志与恢复手段混为一谈。

| 方向 | 需要掌握或了解什么 | 准备到什么程度 |
| --- | --- | --- |
| 日志与持久化 | Redo、Undo、Binlog 的分工；预写日志（WAL）、脏页与刷盘、事务提交和内部两阶段提交 | 能解释为什么提交不必等待全部数据页写回，为什么有 Redo 还需要 Binlog；知道持久性与刷盘配置有关，先理解协调提交的目的 |
| 复制、备份与扩展 | 主从复制、复制延迟、读写分离、备份与时间点恢复；异步与半同步的大致差异 | 能说明写入后读副本可能读到旧值，区分故障恢复与误删恢复；了解高可用切换还要考虑数据与路由，不要求搭建集群 |

容量不足时还会遇到[[database-sharding|分库分表]]。这一阶段只需了解它与加索引、读副本的区别，以及分片带来的路由、跨分片查询和事务成本。分区、在线 DDL、权限与 SQL 注入防护先知道用途和风险；复制协议细节、复杂迁移、页格式与源码分析暂不作为基础准备要求。

建议先学「SQL 与执行流程 → 索引与慢查询」，再学「事务、MVCC 与锁」，最后串起「日志、复制与恢复」。每一组能用一个简单场景解释因果和边界即可继续；这些是待学范围，不表示已经掌握。

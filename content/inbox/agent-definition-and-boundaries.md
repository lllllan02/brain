探索方向：理清「Agent」在本专题中的确切含义，以及它与「LLM 应用」「自动化脚本」的边界在哪里。

可追问：
- 判断一个系统是不是 Agent，最低标准是什么（自主决策、循环执行、工具调用、目标导向）？
- 有没有被过度使用、什么不算 Agent 的典型反例？
- 中文语境下「智能体」与英文 Agent 的用法是否一致？

产出目标：写出一句自己认可的定义，并附 2–3 个正例、2 个反例。

## 回答：定义、判断边界与正反例（初稿）

### 一句话定义（初稿）

**LLM Agent 是以大模型为决策核心、在给定目标下自主决定下一步动作、执行后把结果反馈回决策循环，直到达成目标或主动停止的系统。**

判断口诀：**「谁决定下一步」**——人预先写死的是[[agent-vs-workflow|工作流]]，模型在运行时决定的是 Agent。

### 四个要素，哪条是分界

| 要素 | 是否必要 | 说明 |
| --- | --- | --- |
| 目标导向 | 必要 | 目标需多步才能达成，而非一问一答 |
| 自主决策 | **必要（分界）** | 下一步做什么由模型在运行时选定，不是人写死的分支 |
| 循环 + 反馈 | **必要（分界）** | 观察动作结果，据此修正后续行动 |
| 工具调用 | 常见但非必要 | 只有工具调用、没有自主决策与反馈循环，只是「工具增强的 LLM」 |

最低标准 ≈ 自主决策 × 反馈循环。

### 正例

1. **编码修复 agent**：自己读文档、改代码、跑测试，失败后再改，直到测试通过。
2. **行程代办 agent**：自己搜航班、比价、调用下单工具，失败时换方案重试。
3. **研究检索 agent**：自己规划「检索 → 读 → 再检索」的步骤，直到能回答问题。

### 反例（被过度使用的情形）

1. **单次 LLM 调用**：输入问题直接输出答案，无中间决策 → 只是模型推理。
2. **固定工作流**：人写好「先调 A 再调 B」，LLM 只在某节点做生成/分类 → 流程再长、用了 LLM 也不算 Agent（含超长 DAG）。
3. **定时脚本 / RPA**：规则驱动，同样不算。
4. **只做多轮闲聊的聊天机器人**：没有目标推进和外部行动 → 属于 LLM 应用。

### 中英文用法差异

- 英文 Agent 在 AI 中历史更久（反应式 agent、BDI、RL agent、多智能体系统），**不必然指 LLM 驱动**；说 LLM Agent 时才强调大模型做决策核心。
- 中文「智能体」近两年泛化明显：凡带 LLM 的、甚至 prompt 模板与多角色对话产品都被叫智能体，边界比英文宽。
- 实践建议：讨论时带限定词——「LLM Agent／自主智能体」，避免歧义。

### 产出目标初稿

> **定义**：Agent 是在给定目标下自主决定并执行动作、依据结果调整后续行动，直到完成或停止的系统；LLM Agent 即以大模型为决策核心的那种。
> **正例**：编码修复 agent、行程代办 agent、研究检索 agent。
> **反例**：单次 LLM 调用、人写死的固定工作流（含超长 DAG）。

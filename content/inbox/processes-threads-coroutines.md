进程提供资源与隔离边界，线程是在进程内执行的调度实体，协程通常由语言或运行库在用户态管理。比较它们时，应分别看共享资源、调度者与并行能力，不只比较创建成本。

同进程线程共享地址空间和打开的资源，各有执行栈与寄存器状态。独立栈只是使用方式不同，不会阻止另一线程通过合法指针访问；错误写入也可能影响整个进程。不同进程通过 [[ipc|IPC]] 显式交换数据或共享内存。

内核可以把多个线程安排到不同 CPU。协程能否并行取决于实现：单线程事件循环一次只能执行一个任务，Go 的 [[go-scheduler|goroutine 调度器]] 可以把多个 G 分配到多个线程并行运行。不能把所有协程都定义成“只有一个线程、不能使用多核”。

线程 API 还涉及生命周期。以 pthread 为例，传给线程的参数必须活到线程读取完；栈上对象并非绝对禁止，只要调用者在退出前正确等待。线程也不能返回已经销毁的自身栈地址，资源应通过 join 或 detach 等协议管理。

切换成本受工作集、缓存、系统调用和实现影响；轻量任务也需要栈、队列与状态，数量增长仍要受 [[backpressure|容量约束]] 控制。

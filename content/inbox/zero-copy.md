零拷贝通常指减少 CPU 在内核与用户缓冲区之间的冗余复制。数据仍需经过设备与内存，是否还能省去内核内部复制，取决于接口、设备和协议路径。

传统文件发送可以先 read 到用户缓冲区，再 write 到 socket，中间有内核到用户、用户到内核的复制。Linux sendfile 让内核直接处理文件到输出 FD 的传输，减少这段往返。它仍可能短传输、阻塞或返回错误，调用方需要按返回字节数继续推进。[sendfile(2)](https://man7.org/linux/man-pages/man2/sendfile.2.html)

mmap 把文件页映射到进程地址空间，应用可直接访问这些页，省去显式 read 的一段复制；后续发送若仍复制到 socket 缓冲区，就不能宣称整条链路没有复制。[[device-io|DMA]] 降低设备与内存间的 CPU 搬运工作，与这些机制处在不同层次。

需要用户态压缩、加密或修改内容时，数据路径可能改变，不能仅凭使用某个框架就承诺零拷贝。比较性能应先确定数据从哪里到哪里、由谁搬运、缓冲区何时可以重用，再测量 CPU、吞吐和延迟。

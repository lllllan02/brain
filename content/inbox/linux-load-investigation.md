Linux load average 统计一段时间内可运行任务与不可中断睡眠任务的平均数量。它不是 CPU 使用率，所以磁盘或其他内核等待也可能造成 load 高、CPU 不高。

先结合有效 CPU 核数和容器配额判断排队规模。`vmstat 1` 中的 r 可辅助观察等待运行的任务，b 可提示阻塞任务；再用 `ps` 查看进程或线程状态，检查 D 状态任务等待的资源。以下工具名称是排查示例，未在目标机器运行。

| 线索 | 后续检查 |
| --- | --- |
| 可运行任务多、CPU 饱和 | 热点线程、配额限流、过多并发 |
| D 状态任务多 | 磁盘、网络文件系统、内核栈与设备错误 |
| 磁盘延迟升高 | `iostat -x 1` 的延迟、队列与吞吐，结合设备能力 |
| 内存压力或交换 | 可用内存、缺页、swap 和压力指标 |

iowait 是 CPU 空闲时间的一种归类，不能当作所有 I/O 等待时长。iowait 很低也不能排除 I/O 瓶颈；现代并行设备上，单看磁盘利用率接近 100% 也不足以断定已经达到性能上限。

在 Kubernetes 环境中，从异常 PID 的 cgroup 找到容器，再通过容器运行时定位 Pod 和工作负载，同时排除节点守护进程。仅从 Pod CPU 排名查起，可能漏掉导致全节点阻塞的存储或内核问题。

是否扩容取决于瓶颈：CPU 排队可以考虑加算力，远端存储卡住或锁竞争则需要处理对应资源。

**Agent 每次调用模型前，由程序把指令、当前任务信息和相关历史组织成输入，并附上可用工具的定义。** 拼接不一定是合成一段文字，也可以是按角色排列的消息列表。

例如，用户要求修复登录问题，Agent 已修改代码，准备验证。一次调用的输入可以简化为下面这样；这是示意，不限定具体 API 格式：

```text
指令：你是编程助手，修改后需要验证。
任务状态：代码已修改，尚未验证。
历史消息：
  用户：修复登录问题，只修改 auth.py。
  助手：请求读取 auth.py。
  工具：返回文件内容。
  助手：请求修改 auth.py。
  工具：修改成功。
可用工具：读取文件、修改文件、执行命令，以及各自的参数定义。
```

模型据此决定运行测试，返回工具调用请求。程序执行后，把「请求 + 对应结果」追加到历史：

```text
助手：请求执行测试，调用 ID 为 test_1。
工具：test_1 的结果——测试失败，登录接口仍返回 401。
```

下一次调用重新组装输入时，就包含了这两条新增消息，模型才能根据失败原因继续处理。若同时维护[[agent-task-state|任务状态]]，可依据结果将「尚未验证」更新为「测试失败，待继续修复」，再提供给模型。

这里发生的是「准备输入 → 调用模型 → 执行工具 → 把结果加入下一次输入」。一次用户提问可以重复这个过程多次，直到模型给出最终回答。

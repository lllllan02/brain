普通缓冲文件 I/O 中，write 返回成功通常只表示内核接受了这次写入。应用要获得崩溃后的持久性，需要正确处理短写与错误，并同步文件内容及必要的目录变化。

`fflush` 把用户态缓冲送入内核；`fsync` 同步文件数据和相关元数据；`fdatasync` 可以省略不影响后续读取的部分元数据。直接 I/O 主要改变缓存路径，并不自动等价于同步落盘。设备还必须正确执行缓存刷新等持久化请求。

## 如何替换一个配置文件

下面是 Linux 本地文件系统中常见的设计流程，需结合目标文件系统保证验证，未执行故障注入测试：

1. 在目标文件同一目录创建临时文件，循环写入完整内容，检查短写和错误。
2. 对临时文件调用 fsync，确认数据已同步。
3. 用 rename 原子替换目标名称，检查操作结果。
4. 对父目录调用 fsync，使目录项变化持久化；关闭文件时仍检查错误。

[[files-and-directories|rename 的原子替换]] 让其他进程打开目标名称时得到旧文件或新文件，但它本身没有承诺全部数据和目录项已经落盘。跨文件系统 rename 也不能直接套用这套原子替换流程。

## 文件系统有日志为什么还不够

[[crash-consistency|文件系统日志]] 主要保护其自身更新协议，通常不自动把应用跨多个文件的更新组成事务。数据库或应用仍要定义提交点、恢复方法与返回成功的条件。

接口边界见 [fsync(2)](https://man7.org/linux/man-pages/man2/fsync.2.html)；基础来源为 [OSTEP 第 39 章](https://pages.cs.wisc.edu/~remzi/OSTEP/Chinese/39.pdf)。

---
title: "OAuth 如何让第三方获得有限权限？"
category: "身份认证"

---

OAuth 让资源所有者授权第三方访问指定资源，而不把自己的登录密码交给第三方。它解决委托授权；需要确认登录身份时，应使用 [[sso|OIDC 等身份协议]]。

授权码流程中，客户端把用户带到授权服务器；用户授权后，服务器把短期、一次性的授权码送到已登记的回调地址。客户端再用授权码换取访问令牌，资源服务器根据令牌的权限和接收方决定能否处理请求。

授权码需绑定客户端和回调地址。PKCE 通过 code challenge 与 code verifier 绑定发起授权和兑换授权码的一方，降低授权码被截获后的风险。公开客户端必须使用 PKCE，机密客户端也推荐使用；客户端认证与 PKCE 解决的问题不同。

客户端必须把回调与自己发起的流程对应起来，并具备防 CSRF 措施；常见实现使用不可预测且与会话绑定的 state。回调地址应严格匹配，不能允许任意跳转地址，令牌也不应放在容易泄露的 URL 查询参数中。

资源服务器验证令牌时，除签名外，还需核对签发方、接收方、有效期及 scope。令牌可以是 JWT，也可以是不透明引用；后者通常通过服务端查询确定状态。scope 只能表达授权上限，具体业务资源权限仍需校验。

刷新令牌需要受保护地保存，按客户端类型采用轮换或发送方约束，并考虑撤销与重复使用检测。安全要求见 [OAuth 2.0 Security BCP（RFC 9700）](https://www.rfc-editor.org/rfc/rfc9700.html)。

**网络边界限制程序能连接谁，防止它把可读数据随意发出去，或访问任务不需要的服务。** 能读取项目源码，不等于应该允许把源码上传到任意网站。

| 任务需要什么 | 怎么开放网络 |
| --- | --- |
| 只处理本地文件、离线编译测试 | 禁止外部网络连接 |
| 只访问内部服务 | 允许指定地址与端口，例如测试数据库，其余连接拒绝 |
| 只访问部分外网 | 通过受控代理允许指定域名，同时限制绕过代理的直连 |
| 需要广泛访问互联网 | 放开互联网出口，仍可保护宿主、内网和云元数据服务 |

这些主要是「出站」规则；外部能否连接沙箱内的服务属于「入站」，另行配置。不发布端口并不能阻止程序向外连接。

访问未允许目标时，可以直接拒绝，也可以进入[[sandbox-execution|审批流程]]：批准后只为本次请求、本次任务或长期清单放行，范围由产品与策略决定。**审批决定是否扩大权限，网络规则负责实际限制。**

地址与端口控制连接哪台服务；域名控制哪个网站；精确到 URL 路径、GET／POST 等方法，需要能检查 HTTP 内容的代理或网关。批准域名不等于只批准一条链接，也不自动限制上传内容或[[sandbox-credentials|API 操作权限]]。

[[docker-sandbox-practice|Docker]]、[[srt-sandbox-practice|srt]]和[[e2b-sandbox-practice|E2B]]提供不同配置入口。仅设置代理变量不是强制隔离，已有 socket 等通道也需检查；[[claude-sandbox-network|Claude 运行时源码]]展示限制直连与代理转发的配合。

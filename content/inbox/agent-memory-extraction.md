**记忆提取是从交互中筛选具有跨会话复用价值的信息，形成待校验的候选条目。** 提取时机、内容与校验方式需要一起设计。

[[long-term-memory|长期记忆]]的候选包括稳定偏好、重要事实、长期目标、决策和可复用经验，也可以包括需要跨会话延续的短期计划。判断依据是未来复用价值、与用户或任务的相关性、来源可靠性，以及是否已被覆盖。模型推测不应直接当作用户事实保存。

| 触发策略 | 收益 | 代价与限制 |
| --- | --- | --- |
| 每轮检查 | 更新及时 | 若每轮调用模型，成本增加，也容易生成碎片化条目 |
| 每隔若干轮或时间批量提取 | 结合更多上下文，减少重复调用 | 更新有延迟，需确保待处理历史仍可读取 |
| 事件触发 | 用户要求记住、阶段完成或压缩前集中处理 | 依赖事件，可能长时间不触发；会话未必有明确结束信号 |

可采用混合策略：明确保存或纠正请求及时处理，压缩前检查尚未保存的重要信息，周期任务补充兜底。提取可以异步执行以减少主流程延迟，但完成前其他会话可能读到旧记忆；需要立即生效的变更应等待写入确认。[同步与后台写入的取舍](https://docs.langchain.com/oss/python/concepts/memory#writing-memories)

提取流程可组织为「读取待处理交互 → 按规则识别事实及适用条件 → 生成候选条目 → 校验来源、结构与权限」。模型负责提出候选，程序校验；是否重复、替代或冲突，再交给[[agent-memory-update|记忆更新]]判断，不能把每次提取都直接变成新增。

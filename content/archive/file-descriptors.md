文件描述符（FD）是进程用来访问已打开资源的整数句柄，socket 是一种通信端点，系统调用是程序请求内核操作这些资源的入口。三者分别对应标识、资源和操作边界。

进程通过描述符表找到内核的 open file description，其中保存文件偏移、状态标志等信息。`dup` 或 `fork` 可以让不同 FD 指向同一份描述，因此它们可能共享偏移和非阻塞状态；FD 数字相同的两个无关进程却不一定访问同一资源。[open(2)](https://man7.org/linux/man-pages/man2/open.2.html)

0、1、2 约定为标准输入、输出和错误，但可能被重定向或关闭，并不固定对应键盘与屏幕。FD 也会被关闭后复用，异步任务不能只凭旧数字判断资源仍是原来的连接。

socket 保存协议、缓冲区和通信状态。已建立的 TCP 连接支持全双工，即双方可以同时收发；半双工则需要轮流传输。双工描述传输方向，不决定应用是否必须按请求—响应顺序交互。TCP 已建立连接可用协议及双方地址、端口识别，但监听 socket、UDP 和 Unix domain socket 的寻址语义不同，不能把所有 socket 都等同于一条 TCP 五元组连接。

`read`、`write`、`accept` 等系统调用跨越用户态与内核态边界，但不一定导致线程调度切换，也不一定触发磁盘或网卡访问，例如文件内容可能已在页缓存。调用还可能只处理部分数据、遇到 EOF 或返回错误，应用必须按返回结果推进缓冲区。

普通文件的名字、inode 与打开引用的关系见 文件和目录。

FD 的阻塞标志决定未就绪时调用如何返回，[[io-models|I/O 模型]] 决定程序如何等待与继续；[[io-multiplexing|多路复用]] 则让一个等待点关注多个 FD。

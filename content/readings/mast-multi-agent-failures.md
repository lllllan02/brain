**「多 Agent 的错误既可能来自单个执行者，也可能来自分工、信息传递与结果验收。」** 本文节选《Why Do Multi-Agent LLM Systems Fail?》v3（2025-10-26）的分类方法和主要限制，重点对应正文第 3—5 节与附录 A。

作者先分析约 150 条执行轨迹建立分类，再形成包含 1,642 条轨迹、覆盖七个系统的数据集，并用经人工校准的模型标注器扩大分析。分类包含十四种失败模式，归入系统设计、Agent 间失配和任务验证三组。

可观察的例子包括违反任务或角色约束、重复步骤、丢失历史；不澄清歧义、忽略其他成员输入、行动偏离推理；以及过早终止、缺少验证或验证错误。它们能帮助把「答案错了」定位到具体协作环节。

论文给出的 ChatDev 干预案例通过保证指定决策者掌握最终结束权改善结果，说明控制流也会影响成功率；单点修复不保证普遍可靠。

这些标签来自选定系统、模型和任务，作者未声称穷尽所有失败。标注一致性不等于每条因果归因都已证实，观测到的失败率也不能直接当作新模型或任意多 Agent 架构的失败概率。

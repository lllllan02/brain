**递归语言模型（Recursive Language Model，RLM）把长输入和中间结果保存在可编程环境中，让模型用代码选择、转换并分派片段，最终从环境中的变量取得答案。** Alex L. Zhang、Tim Kraska、Omar Khattab 的论文研究模型外部的推理框架，本文依据 2026-05-11 的 v3。

它没有扩大底层模型一次调用的窗口。增益来自把大任务改为多次受控读取、语义处理和程序合并；每个子调用仍受模型能力与窗口限制。

## 为什么检索或摘要有时不够？

找一个名字时，只需少量片段；统计每条记录的语义类别时，几乎所有记录都可能影响答案；比较记录对时，还要处理跨记录关系。随着输入增长，所需处理量并不相同。

| 任务形态 | 论文例子 | 对上下文处理的要求 |
| --- | --- | --- |
| 找少量证据 | 单针检索、BrowseComp-Plus 多文档问答 | 搜索后集中处理少量证据 |
| 全量语义汇总 | OOLONG | 逐项理解，再聚合结果 |
| 大量配对关系 | OOLONG-Pairs | 组合多个记录，不能只取少量高相似片段 |

作者据此质疑通用的先摘要策略：如果大多数细节都会参与计算，提前判断哪些可以丢弃很困难。这是对任务处理密度的区分，不等于宣称检索或摘要应被全面替代。

## 一次运行的数据怎样流动？

1. 程序把完整输入保存成 REPL（交互式执行环境）中的字符串变量，向根模型提供长度、短预览和访问方式。
2. 根模型生成代码，检查结构、筛选或切分输入。原始长字符串无需复制进根模型消息。
3. 代码可在循环中对子片段调用模型或子 RLM，并把结果保存为变量。数值汇总、去重和拼接可交给程序。
4. 执行反馈以受限长度返回，根模型据此修正下一步；最终把答案写入约定变量，框架读取该变量返回。

论文特别区分三个设计点：输入有可操作的句柄，中间结果留在环境，模型调用能由程序批量发起。只有代码执行工具，再单独增加一个手工填写的子 Agent 工具，未必具有相同的数据流。

解释性例子：对大量客服记录统计问题类别，可先检查记录格式，分批让子模型判定类别，存下结构化结果，再用程序计数。这个例子用于说明机制，不是论文中的实测任务；错分和漏分仍需检查。

## 哪些对照证明了什么？

主实验比较直接调用、CodeAct、摘要 Agent、编码 Agent 及不同递归深度的 RLM。GPT-5 作为根模型时，RLM 子调用使用 GPT-5-mini；摘要基线为控制成本使用 GPT-5-nano 压缩、GPT-5 回答。因而结果比较的是这些具体系统配置，不能完全归因于框架结构。

表 1 的 GPT-5 组部分结果如下；OOLONG 为任务分数，OOLONG-Pairs 为 F1，不能横向当成同一种成功率。金额为论文当时的平均 API 成本。

| 方案 | OOLONG：分数／成本 | OOLONG-Pairs：F1／成本 |
| --- | --- | --- |
| 直接调用 | 44.0／$0.14 | 0.1／$0.16 |
| 摘要 Agent | 46.0／$0.13 | 0.1／$0.13 |
| RLM，不允许子调用 | 36.0／$0.37 | 43.9／$0.69 |
| RLM，最大递归深度 1 | 56.0／$0.43 | 58.0／$0.33 |

外置输入本身已能帮助某些任务；语义密集任务进一步受益于子调用。但在 OOLONG 上，深度 1 比摘要方案更贵，不能把总体效率描述成处处降本。论文中将上下文外置到文件的普通编码 Agent 也获得明显改善，说明比较时不能忽略数据放置方式。

## 递归越深，效果越好吗？

不是单调关系。GPT-5 在配对任务上增加深度有收益，但 Qwen3-Coder 在部分任务上更差；作者观察到它产生更多语法错误，递归会把执行错误传播到子调用。首轮如何分解任务也影响结果，论文用分解示例和提示做了相关实验。

费用存在长尾：少数反复寻找答案的轨迹会拉高均值。论文实现中的调用是阻塞、顺序执行，因此 API 成本相近不等于延迟相近。子调用数量失控、较弱模型的编码能力，以及真实长任务上的泛化仍是限制。

## 能否训练模型更好地使用这个框架？

v3 还报告了训练结果：使用约 1,000 条筛选后的 RLM 轨迹训练 Qwen3-8B，提高它操纵 REPL 和选择子调用的能力，在其他长上下文任务上也获得改善。它提示框架使用能力可以学习；这部分增益包含参数训练，需与只给现成模型套框架的实验分开。

阅读判断：[[complexity-trap-summary|屏蔽旧观察]]主要降低交互历史成本，RLM 主要组织大输入的计算；两者可能服务同一系统的不同部分。判断是否引入 RLM，应先问任务需要少量证据还是全量语义处理，再对照相同底层模型下的成功率、调用数、总成本与延迟。

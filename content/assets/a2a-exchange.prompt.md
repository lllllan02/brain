Objects and relationships:
1. 左阶段：上方是主应用的轻量浏览窗口。向下箭头标「读取能力卡」，下方文件夹中取出折角能力卡 Agent Card，卡内两行「生成报告」「地址 · 认证」。能力卡向上返回主应用，箭头方向准确。可用一条向下请求线、一条向上返回线，不要互相覆盖。主应用取得地址后进入中阶段。
2. 中阶段：上方主应用旁是蓝色需求信封 Message，包含两项可辨认内容「分析需求」「sales.csv」。向下发送，线标「POST /message:send」。下方报告服务接收，在其内部用一个暖橙色插口／代码页签「执行器」连接小型模型与工具符号，旁边画一张数据表格，箭头表示它读取数据并执行；标短语「调用模型与工具」。任务单 Task 清晰写「t1」以及「排队 → 执行中」。从任务单向上有独立返回箭头「先返回 t1」，表明先接受任务、后执行。向下发送和向上回执分开。小字条件「returnImmediately: true」贴在返回箭头附近。不能画成执行结束后才返回 t1。
3. 右阶段：主应用已经持有一张小任务编号票据 t1。向下查询箭头标「GET /tasks/t1」，报告服务下方有完成的工作单 Task「t1 · 已完成」，旁边是带折角、简短趋势图和正文线条的报告纸 Artifact，写「销售报告」。向上返回箭头同时带回状态与报告，短标「状态 + 报告」。在 GET 请求旁画小回环，标「执行中：间隔查询」，回环只表示查询重复，不重复提交任务；「已完成」时结果返回后结束。
Semantic invariants: Message 是请求内容，Task 是服务端的工作记录，Artifact 是成果；模型／工具执行发生在报告服务内部。任务编号 t1 在提交回执、执行和查询阶段一致。先返回 t1 的条件是 returnImmediately: true；图中采用这一模式。查询不新建任务。主应用的程序发网络请求，图中不画模型直接操作网络。

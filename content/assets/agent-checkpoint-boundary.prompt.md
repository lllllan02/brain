Use case: infographic-diagram.
Asset type: 中文知识笔记中的辅助解释图，横向 1536×1024 左右，清晰中文。
Primary request: 解释程序运行过程中的“哪里是检查点”：开发者或框架在阶段边界设置保存动作，保存成功后形成持久检查点；后续阶段中断，新进程从该记录指定的阶段重新执行。只用通用阶段 A、B、C，不使用草稿、审批、发布、订单等业务例子。

Reference image: /Users/lllllan/lllllan02/horizon/.agents/skills/excalidraw-diagram/assets/diagram-style-reference.png 仅为风格参考。只迁移二维技术编辑插画的文档造型、薄轮廓、局部淡彩、规整中文和留白。完全不复用样图内容或布局。

Style: 克制的二维技术编辑插画，白色背景，细而清楚的深灰蓝轮廓。使用少量折角纸张、进度刻度、保存位置标记使对象可辨认。避免纯方框文字堆砌。没有机器人、齿轮、光效、3D、明显渐变、厚阴影、页尾口号或总结面板。
Palette: #ffffff 背景；#374151 主要文字；#64748b 辅助文字；#416788 和 #eaf0f7 表示成功保存与恢复读取；#b66a43 和 #fbf0e6 表示中断与未保存进度；#a8b3c2 轻边界。

Composition and semantic invariants:
整图围绕一条横向执行轨道和它下方的一份检查点记录组织；下方再画恢复运行轨道。时间均从左向右。
1. 顶部适度标题“检查点在程序的哪里？”，小副标题“保存位置由开发者或框架设置”。
2. 主轨道行标签“原运行”：左侧“阶段 A”已经完成，用完成刻度和结果纸张表示；其右侧、进入阶段 B 之前，轨道上显著但小巧的蓝色定位标记，标记文字“保存成功”“检查点”。检查点是 A 与 B 之间选定的保存位置，绝不能画到 B 内部、也不能放在中断点。之后是“阶段 B”，内部半截橙色进度刻度，阶段 B 中间一个橙色停止符并标“中断”。最右“阶段 C”浅灰虚线、标“尚未执行”；B 到 C 的预定轨道只用细灰虚线，不暗示原运行已经继续。
3. 从 A 与 B 之间的蓝色保存标记竖直向下箭头“写入”，落到中层一份折角文档上。该文档是主要解释对象，标题“持久保存的记录”，内部两条明确字段“已有结果：阶段 A 的结果”“下一步：阶段 B”。纸张置于小型数据库/存储轮廓上，可贴“数据库 / 文件”标签，不加额外系统。
4. 下方行标签“恢复运行”：从同一份持久记录向下箭头“读取”，接一个简洁恢复入口，再从左向右进入“阶段 B”，该阶段显示起始进度，文字“重新执行”；继续到“阶段 C”，文字“继续执行”。原运行和恢复运行的 B、C 尽量上下对齐。
5. 紧邻原运行 B 的未完成进度标注“未保存的进度需重做”。这句只就近说明 B，不额外画独立告示框。持久记录中的 A 结果原样被复用，无需再运行 A。
6. 用保存标记的精准位置、保存箭头落到数据记录、读取箭头再指向 B 来说明机制。严格区分蓝色检查点和橙色中断位置；没有回到任意代码行的箭头。不要额外讲审批、幂等、外部副作用等其他问题。

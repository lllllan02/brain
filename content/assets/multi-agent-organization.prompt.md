Primary request: 在一张紧凑的对照插画里展示协作组织的五种运行方式。上排解释任务调度：主从委派、路由、交接；下排解释成员协调：群聊、共享任务。它们可以组合，不画成五选一的决策树。本图不解释工具调用、网络协议或 A2A。

Composition: 白底，无大外框。上方三个宽度相等的小型场景横排，下方两个稍宽场景并排，用很轻的分隔线和两条行标签建立层次。行标签“任务调度”和“成员协调”小而清楚；每个场景名称可直接定位。标题“协作组织怎样运转”适度，不压过图。每个场景都有实际的上下文工作窗、任务票据、成果文档或消息对象，不只是名词节点。
Top left 主从委派: 一个主 Agent 上下文窗在左，两个小子 Agent 工作窗 A/B 在右上、右下。主 Agent 向两者分别发出蓝色“任务”箭头；两者分别以橙色“成果”箭头回到同一个主 Agent。两个方向分别连接不同端口，避免重叠，至多一个转角。清楚表达调度与汇总留在主 Agent。
Top middle 路由: 一张“请求”票据进入一个很小的分流器，分流器旁标“按类别”；右边专家 A/B 两个上下文窗，当前选中的 A 有蓝色清晰连线，B 只有很轻的灰色未选支路。不要画成主从中所有专家必定同时工作。场景对象标签只有“请求”“按类别”“专家 A”“专家 B”。
Top right 交接: Agent A 上下文窗在左，Agent B 工作窗在中右。一张任务票据和控制权从 A 沿橙色右向箭头交给 B，箭头短标签“转交”；后续对话气泡只接在 B 的右侧。A 淡灰、B 灰蓝表现当前处理者改变；没有成果返回 A 的箭头。标签“Agent A”“Agent B”“后续对话”。
Bottom left 群聊: 三个小成员工作窗 A/B/C 围绕一条“共享对话”消息带。本轮 A 为蓝色当前发言者，一张 A 的消息从 A 进入共享对话，再广播给 B/C；B/C 是接收者，不画成同时发言。标注“轮流发言”“广播”，不要画成单向流水线 A 到 B 到 C，也不要画成无方向的三角网。
Bottom right 共享任务: 一个小型任务板有三列“待认领”“处理中”“完成”，列里是带折角的任务票据。某张票据从待认领移入处理中，票据上贴“负责人 A”；成员 A 用清楚箭头“认领”指向这张正在处理的票据。成员 B 将一份成果文档沿“提交”箭头交到完成列。成员对共享任务状态读写，而不是共同广播全部历史。Agent A/B 工作窗可在板下，勿出现混乱交叉线。

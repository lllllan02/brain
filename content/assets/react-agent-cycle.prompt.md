Style:
克制的二维技术编辑插画，白底，充足留白，规整清晰的中文印刷字体，适度标题。对象以具体形状表达：推理用有页签的决策笔记，工具用有小图表的监控终端，观察用折角结果单，输出用简短结论文档。中等偏细的灰蓝轮廓，适度圆角，少量内部细节。不要将三个对象画成相同矩形卡片。禁止机器人、发光脑球、3D平台、厚重阴影、粗黑线、明显渐变、笔刷标题、装饰图案和页尾口号。
Palette: #ffffff 背景；#374151 文字和主要轮廓；#64748b 次要文字；#416788 与 #eaf0f7 表示推理与行动主线；#b66a43 与 #fbf0e6 表示新证据及返回判断的反馈；#a8b3c2 为辅助细节。颜色使用面积克制，不能以整块背景分栏。
Aspect: 横向约 16:10，高分辨率；画面紧凑但文字留足宽度。

Objects and relationships:
主线从左到右，三个实际对象依次为：
1. 决策笔记，旁边标签「推理 Thought」，对象内为「模型选择下一步」「目标：定位变慢原因」「先查运行指标」。
2. 监控终端，旁边标签「行动 Action」，对象内为「程序执行工具」「读取运行指标」，画少量中性小图表，仅示意工具对象，不添加数字或额外文字。
3. 折角结果单，旁边标签「观察 Observation」，对象内为「数据库正常」「应用 CPU 偏高」，后者小面积暖橙突出。

结果单的下沿向下延伸一条暖橙反馈路径，经画面下方从右向左返回决策笔记下沿；箭头必须朝向决策笔记。此路径可用柔和圆角的回环，避免交叉，标签「据此改查应用调用栈」。它表明结果更新下一轮判断，不能将反馈直接连到工具。
在决策笔记的上方偏右，放小型结论文档「输出结论」。从决策笔记上沿引出一条向上的细蓝箭头指向该文档，箭头旁写「信息足够」。该出口比主循环轻，不与主流程或标题相撞；不要从观察直接连接最终结论。

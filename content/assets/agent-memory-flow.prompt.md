Composition: 这是一张整体机制图，主线从左到右。中心是同一份记忆存储，左侧是写入侧，右侧是读取侧。左上与右上各有一个短触发条件区，下面接对应操作节点。主体纵向居中，画面分为五列：信息来源、写入处理、记忆存储、检索处理、当前输入与使用。宽度分别约 14%、22%、23%、22%、19%。所有连接只用水平或垂直直线，必要时最多一个直角。整体语义不是所有组件同步执行；左右两条路径可以发生在不同任务和不同时间。

左侧信息来源：上面是两条简化聊天气泡，标签「用户交互」；下面是一张带勾选项的执行报告，标签「执行结果」。它们一起进入写入处理，不放具体项目或代码语言案例。
写入处理上方触发标签：「何时写入」，三行短文「明确长期要求或纠正」「确认有后续用途的事实」「任务收尾提炼经验」。下面放一个筛选台，标题「筛选与更新」，台中两条短标签「核对用途、范围与来源」「新增／补充／纠正／删除」，右侧橙色箭头进入记忆存储，箭头标签「写入」。筛选台下方两行很小但清楚的限定「可在交互中或后台处理」「无可复用内容就不写」；不把后台画成必须的单独服务。
中心记忆存储：一个较大的带页签档案夹，主标签「记忆存储」，页签「文件／数据库」。内部三张有折角、有浅灰正文线的记录纸，其标题依次为「偏好与约束」「事实与决定」「有前提的任务经验」。三类文字全部能看到。档案夹下面靠近记录位置短小标注「每条保留：内容、范围、来源」，下一行次要标注「按需维护版本与有效状态」。记录表示保存对象，不是模型当前输入，绝不能把模型画在档案夹内。
检索处理上方触发标签：「何时检索」，两行「任务开始」「发现信息缺口」。下面是筛选漏斗或叠放的候选记录选择器，标题「按当前任务检索」。在选择器中显示三张小候选纸，第一张浅蓝标「当前用户／项目」「有效且相关」，另外两张浅灰标「范围不符」「已过期」，不让浅灰条目流入输出。存储右侧有一条蓝箭头进入检索选择器；只有浅蓝候选的输出端箭头进入右侧上下文，箭头标签「取回所需片段」。下方就近小字「先限定用户、项目与权限」。
最右列：一张折角文档主标签「本轮上下文」，内有三条简短内容「当前任务」「相关记忆」「指令与工具」。下方通过一条短垂直箭头连到极简节点「Agent 继续任务」，节点里只画简化的文本响应与工具符号，不用卡通机器人。上下文文档外有一行短注「当前明确要求优先」。不要添加输出事实自动无条件写回的箭头；结果会成为左侧“执行结果”的来源，但保存依旧受写入时机与价值判断控制。
Semantic invariants: 写入时机、写入内容、物理存储、读取时机、检索条件与最终使用必须各有对应位置。用户交互和执行结果是来源，记忆存储中的三类条目是所保留内容，二者不可混为“全部聊天自动保存”。模型不直接看到整个记忆库，只用检索后放入本轮上下文的相关部分。记忆存储可以跨任务使用；这不是一条每轮必跑的固定流水线。无需加短期长期工作记忆分类、品牌、向量库、评测或高级图结构。

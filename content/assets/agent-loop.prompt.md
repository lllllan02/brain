Use case: infographic-diagram.
Asset type: 中文知识笔记「最小 Agent Loop」的辅助解释图。
Primary request: 让读者一眼理解最小 Agent Loop：模型根据当前消息提出工具调用，程序执行，把调用和结果追加到历史，带着新历史再次调用模型；模型也可直接返回答案。画得简短、清楚。

Style: 克制的二维技术编辑插画。白底、充足留白，深灰蓝中细轮廓，小面积低饱和淡彩。对象应有形象：消息是叠放的纸页，模型是简洁的小型计算面板，工具执行是代码文件与执行窗口；不使用机器人或发光脑球。不要统一成步骤方框。字体规整、中文清晰、标题适中。不加装饰徽章、渐变、立体平台、厚重阴影、底部口号。
Palette: 深灰 #374151 文字与轮廓，灰蓝 #416788 与浅蓝 #eaf0f7 表示消息与模型输入，暖橙 #b66a43 与浅橙 #fbf0e6 表示工具请求和执行。次要文字 #64748b。
Aspect: 横向约 3:2，整体紧凑，适合短篇笔记。

Objects and relationships:
主线从左到右：消息历史（叠放纸页，初始含「用户问题」）→ 每轮入口「检查轮数」→「模型」→ 右侧「程序执行工具」。模型到工具的箭头标「工具调用」。工具执行对象中有一张小结果纸条「结果 / 错误」。下方反馈路径从工具出发，标「追加调用与结果」，清楚指回左侧的消息历史；读者随后能沿消息历史→检查轮数→模型再次读回同一路径。反馈可以用下方舒缓的回转箭头，主线保持水平。消息历史用纸页内部的三条记录「用户问题」「工具调用」「工具结果」来展示累积，初始只含用户问题通过旁边轻标签「初始」注明即可，不复制第二份历史。
模型另有一条向上的短分支，标「最终回答」，连接独立的答案纸页「返回答案」。每轮入口另有一条向下的短分支，标「达到上限」，连接小而清晰的退出标签「停止：任务可能未完成」。主循环、返回答案和轮数上限退出都必须清晰可达。
Semantic invariants: 执行工具的是程序；反馈回到消息历史，再经过检查轮数重新调用模型。最终回答和工具调用是两条分支。达到轮数上限是中止，不能标成成功。不加入任务验收、反思、规划、重试或权限系统。

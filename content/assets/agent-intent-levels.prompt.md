Composition and exact content:
顶端适度标题“意图判断发生在哪里？”，小副题“订单查询 · 假设示例”。
三行共享“请求在左、判断在中、候选能力在右”的视觉位置。每行单独一张折角票据，文字完全相同：“查订单 A”。每行只高亮一个被选中的出口，未选候选保持浅灰且不画同样强的流向箭头。
第一行行名“单 Agent”。用轻虚线边界标记“Agent”，边界内左部是模型图标与标签“模型选工具”，此处小面积暖橙强调。请求箭头指向模型。边界内右部三张不同用途的函数文档分别写“查询订单”“搜索文档”“取消订单”。仅从模型指向“查询订单”的蓝色箭头，查询订单文档以淡蓝突出，另两张灰色。可辨认是模型在 Agent 内选工具；不能在外部额外画分类器。
第二行行名“多 Agent”。相同请求指向边界外独立的入口分派节点“入口路由”，此节点暖橙突出。右侧两个独立应用窗口分别为“订单 Agent”“技术支持 Agent”，仅指向订单 Agent 的蓝色选中箭头，技术支持 Agent 为灰色候选。路由节点必须在两个 Agent 窗口之外。
第三行行名“混合系统”。相同请求指向“入口路由”，此节点暖橙突出。右侧三种造型不同的候选：“订单接口”（服务器与端口造型）、“退款流程”（三个相连的小步骤组成的流程面板）、“通用 Agent”（应用窗口造型）。只选中“订单接口”，另外两个灰色。图中不能暗示必须先进入 Agent 再调用接口；接口、固定流程、Agent 是并列处理入口。
Semantic invariants: 三行是不同系统的对照，不是同一系统的三个先后步骤；暖橙只表示意图判断位置，蓝色表示当前请求选中路径。候选名称和请求必须可读。模型选工具本身就在完成意图识别。
Text: 仅呈现上述标题、小副题、三行行名、请求、判断节点和候选对象标签。不增加整段解释、页脚总结或任何未要求的组件。
Validation: 所有文字不裁切、不重叠；所有箭头落在相应对象边缘，每行只有一个选中对象；无跨行连线。保留足够文字宽度，图面清楚但具有参考图的对象插画感。

Composition and objects:
上方适度标题“按成果分组，按依赖排序”，副标题“SSO 假设示例”。
上半部为从左到右四个具体成果快照，灰蓝细水平箭头连接，箭头表示前置依赖：
1. 接入约定纸张，内部两条字段“身份来源”“过期与退出”，有确认勾。下方短标题“接入约定已确定”。
2. 一个浏览器窗口“应用 A”，内部用户小头像和已登录勾，下方短标题“A 能登录并识别用户”。
3. 两个小浏览器窗口“应用 A”“应用 B”，都显示相同用户小头像和勾，中间是一条接入关系，下方短标题“A 登录后，B 免重复登录”。此成果以轻橙细轮廓标选，不用大底色。
4. 小型边界验证清单，三行“过期”“退出”“失败”，每行有勾，下方短标题“边界行为符合约定”。
四个快照各有独立浅虚线范围，含义是子任务边界。每个下方有小验收标签“可检查的结果”。只需要一条全局短注“箭头表示前置依赖”，不要对每个箭头加重复长字。
第三个成果向下连接到下半部左侧的放大子任务纸张，连线是橙色细线且标注“展开这一项”，必须让归属清楚，不与时间依赖箭头混淆。

下半部左侧：一个大的折角任务单，标题“子任务：接入应用 B”，内部三行字段
“前置：A 登录可用、接入约定”
“产物：B 的接入实现”
“验收：A 登录后，B 免重复登录”
任务单下部包住三张小型工作票或图标，依次为“读接入代码”“实现接入”“验证行为”，全都在这个任务单边界内，不各自变成新的子任务。任务单内这三张工作票下方短注“共同完成同一成果，放在一项内”。

下半部右侧：解释停止细分的边界，与任务单并排，放一个小放大镜和两张简洁状态纸：
上面浅蓝勾纸，文本“做法明确 + 验收明确”，一条短箭头到“停止细分”；
下面轻橙未完纸，文本“仍含不同成果 / 关键选择未定”，一条短箭头到“继续细化未定部分”。
用小标题“拆到哪里停？”统一这一区域。不要添加“更高效、更清晰”等优点概述。
Semantic invariants:
- A 的可用登录是示例中 B 接入的前置；四个成果整体从左到右推进，不能反向依赖。
- 任务边界围绕可检查成果，读代码、实现、验证是同一成果的内部操作。
- 放大区必须对应上方第三项，不可连接到其他成果。
- “停止细分”仅用于已明确做法和验收的这一项，不表示整个 SSO 完成；仍有不同成果或关键选择则继续细化未定部分。
- 这是任务规划示例，不是真实安全架构，勿补造 OAuth、JWT、密码或接口字段。

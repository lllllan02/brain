**长期记忆检索根据当前任务选择相关信息，再交给模型使用；需要同时控制召回时机、相关性和上下文占用。**

## 什么时候检索？

| 检索时机 | 优点 | 代价与限制 |
| --- | --- | --- |
| 每轮交互时 | 触发规则简单，每轮都有机会补充相关记忆 | 重复查询增加延迟与成本，也可能引入无关信息 |
| 任务开始时 | 一次加载，减少后续查询 | 难以覆盖执行中新出现的需求，已加载信息也可能过时 |
| 执行中按需检索 | 根据当前缺口补充，减少无效查询 | 需要判断何时检索，判断失误可能漏召回 |

一种可选取舍是 **「任务开始加载少量相关核心偏好，执行中按需补充」**：既让初始决策有必要背景，又避免每轮重复加载；发现信息不足或已有记忆可能过时时，再查询。

## 用什么方式检索？

- 精确查询：按用户、类型或明确字段查找，适合已知偏好和事实。
- 语义检索：按含义寻找相近内容，适合表述不一致的需求与历史经验。
- 混合检索：组合关键词、结构化条件和向量召回，兼顾明确约束与语义相关性。

## 召回后，哪些内容进入上下文？

处理链路可组织为：

「限定授权范围 → 召回候选 → 过滤失效内容 → 按相关性、重要性与时效性排序 → 按预算选择 → 注入上下文」。

**「召回结果不等于最终输入」**。记忆由[[agent-context|上下文管理]]组织进本轮输入，与已有历史、摘要去重并处理冲突；条数上限不能代替 [[context-budget|Token 预算]]。权限范围应由程序在召回前约束，不能等模型看过其他用户的数据再过滤。

是否改善回答，还需通过[[agent-memory-evaluation|质量评估与归因]]检查模型实际看到了什么、如何使用，以及对任务结果的影响。

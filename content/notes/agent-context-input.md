**Agent 上下文（Context）是一次模型调用实际收到、用于本轮判断的输入信息。**

这里采用「指令 → 当前任务状态 → 本轮可用工具定义 → 对话记录」的逻辑组织顺序：前三项构成每轮调用的基础部分，后面接持续累积的对话记录。

| 顺序与内容 | 包含什么 | 每轮如何传入 |
| --- | --- | --- |
| 1. 指令 | 系统提示词、应用规则、行为约束 | 每轮必带，放在最前面，不随历史裁剪而丢弃 |
| 2. 当前任务状态 | 目标、约束、当前进度、已完成事项与待办 | 有独立[[agent-task-state\|任务状态管理]]时，每轮带入最新相关状态，一般放在系统提示词后面；没有则不单独添加 |
| 3. 本轮可用工具定义 | 工具名称、用途、参数及调用约定 | 每轮提供本轮暴露的工具定义；可以固定提供，也可以按需选择工具后提供 |
| 4. 对话记录 | 用户消息、模型消息、工具调用及结果，也包括通过消息或工具结果带入的文件、检索片段、记忆等补充资料 | 包含本轮用户输入；历史随交互累积，需要选择、裁剪或压缩 |

![[assets/agent-context-input.png|一次模型调用的上下文：基础部分与对话记录]]

以上是逻辑顺序，工具定义可由独立接口字段传入；每轮保留基础部分，不代表内容不变。

[[agent-loop|Agent Loop]] 每轮将「工具调用请求 + 对应结果」追加到历史，再带入下一轮调用。**「即使用户不再发消息，历史仍会增长」**，因此需要[[agent-context|上下文管理]]控制输入规模。

**Agent 上下文（Context）是一次模型调用实际收到、用于本轮判断的输入信息。**

上下文决定模型本轮能依据哪些要求、进度和证据行动。文件、记忆或历史即使已经保存，也要被选入本轮输入，模型才能使用其中的内容。

## 一次调用包含什么？

按信息用途，可以把 Agent 上下文分为四类：

| 内容 | 回答的问题 | 典型组成 |
| --- | --- | --- |
| 指令 | 应按什么要求行动？ | 系统提示词、应用规则、用户的有效要求与行为约束 |
| 当前任务状态 | 任务进行到哪里？ | 目标、约束、已完成事项、关键判断与待办；有独立[[agent-task-state\|任务状态管理]]时带入最新相关记录 |
| 本轮可用工具定义 | 能请求哪些操作、怎样调用？ | 工具名称、用途、参数和调用约定；说明可调用接口，实际操作由程序执行 |
| 对话记录与补充资料 | 已经发生什么、有哪些证据？ | 当前请求、选定的历史消息、模型的工具调用请求及对应结果，以及读入的文件、检索片段和记忆 |

这是一种用途分类，具体消息角色、排列顺序和接口字段由实现决定。例如，用户消息既可以提出约束，也可以附带日志；工具定义可以通过独立字段提供，任务状态也未必单独成块。**用途分类不能代替指令优先级或授权判断**，外部资料中的命令不能仅因进入上下文就成为用户要求。

## 下一轮调用，哪些内容会变化？

[[agent-loop|Agent Loop]] 将模型的工具调用请求与执行结果加入历史，再组织下一轮输入。即使用户没有发送新消息，工具交互也会使历史增长；保存的历史可以持续增加，本轮带入的部分则受窗口和任务需要限制。

每轮保留当前有效的指令，更新任务状态，提供本轮暴露的工具定义，并选择必要的消息和证据。[[agent-context|上下文管理]]负责这些内容的选择、更新与缩减，不能把整份输入都当作只追加、不更改的聊天记录。

## 外部资料什么时候进入上下文？

资料经过读取、检索或记忆召回，并随消息或工具结果提供给模型后，才成为本轮上下文。[[anthropic-context-engineering-summary|Anthropic 的按需加载实践]]先保留路径或查询，再取回相关内容：路径只能提示资料的位置，不能替代正文；只读入一个片段时，模型也只能直接依据该片段。

## 资料都相关，为什么仍可能漏掉要求？

一次排障输入同时包含新限制、旧方案、完整日志和网页片段，新限制可能淹没在重复材料里，旧方案也可能被误当成当前决定。

装配时标明当前目标、有效约束和进度，提供必要证据与待解决问题；失效方案注明状态，外部内容保留来源。排查漏项时，通过[[agent-trace-capture|上下文采集]]核对当轮实际输入及版本，区分「未提供」「已被裁剪」与「已提供但未遵守」，仅看最终聊天记录无法作出这种判断。

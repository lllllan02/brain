**Agent Trace 是一次 Agent 运行中相互关联的操作记录，用于还原模型获得的信息、提出的动作、程序执行结果与任务验收情况。** 只保存最终回复，无法区分上下文不足、工具选错、执行失败和结果误读。

它沿用 [[trace|Trace]] 与 [[span|Span]] 的结构：模型调用、工具执行等步骤各自记录时间与状态，再通过调用关系组织起来。输入输出为这些步骤补充内容证据；实际能还原多少过程，取决于埋点、采集和保留策略。

## 从记录到使用，分别要解决什么？

一次观测要走过「创建节点 → 关联调用 → 保存证据 → 导出核验 → 查看分析 → 回归改进」。下面六篇各回答一个环节，沿用 `labs/agent-trace/` 的 Eino 与 Langfuse 实验；每篇只取服务于该问题的代码与数据。

| 问题 | 展开内容 |
| --- | --- |
| 怎样创建和结束一个 Span？ | [[agent-trace-spans\|Span 创建与结束]]：根运行、自动模型／工具回调、业务埋点、流式与取消收尾 |
| 并行、重试、恢复怎样连起来？ | [[agent-trace-structure\|调用关联与并行记录]]：Context、父子关系、调用 ID、独立 attempt 与跨入口关联 |
| 模型实际看到什么，能保留多少？ | [[agent-trace-capture\|内容采集与保留]]：原始结果、内容加工、实际请求、脱敏、大载荷与采样 |
| 怎么知道记录没有漏，结果是否可靠？ | [[agent-trace-verification\|采集可靠性]]：本地断言、导出损失、平台读回，以及采集可信与业务正确的区别 |

## 每一层需要记录什么？

下表是面向排查与评测的建议，具体字段需映射到所用 SDK；业务验收和版本信息由应用补充。

| 层次 | 需要保留的信息 | 能回答的问题 |
| --- | --- | --- |
| 任务与运行 | 用户输入、目标与约束、任务和会话标识、开始结束时间、停止原因、最终回复 | 为什么开始，为什么结束？ |
| 模型调用 | 实际发送的消息与工具定义，检索或记忆内容，模型与参数、Prompt 版本，响应与调用提议、token 用量 | 模型看到了什么，选择了什么？ |
| 工具与控制步骤 | 名称、调用 ID、参数、结果或错误、耗时，重试次数，审批或规则判定，计划变更及依据 | 程序执行了什么，哪里改变了路径？ |
| 结果与复核 | 实际产物或外部状态、验收结果、评分依据、用户反馈，以及代码、工具和数据版本 | 完成声明是否成立，改版后能否比较？ |

工具原始结果与下一轮模型实际收到的内容可能不同，筛选、摘要和截断也需要有据可查。内容采集篇说明在哪里采集、怎样保存版本引用，以及脱敏和采样会限制哪些判断。接口未暴露的内部推理不能通过 Trace 自行取得。

## 怎样从失败记录验证改进？

例如查订单 A 却回答 B，应顺着模型输入、调用参数、工具结果和最终回答寻找首次偏离的位置，再验证候选原因。**「调用未报错」不等于「任务完成」**，还需要实际产物、业务状态或独立评分作为依据。

错例回归篇把这条排查路径展开为可重新执行的测试：固定输入与必要环境，补充验收条件，比较新旧运行。保存 Trace 不保证精确重放；模型随机性、外部数据变化和写操作副作用仍需控制。从中断处继续任务则依赖[[agent-checkpoint-recovery|检查点与恢复机制]]。

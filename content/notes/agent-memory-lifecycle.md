**[[long-term-memory|长期记忆]]可以跨会话使用，但不一定永久有效：按信息的适用时间决定失效，按复用价值决定是否保留。**

## 有效期怎么设？

| 信息特点 | 处理方式 |
| --- | --- |
| 失效时间明确，如明天的面试计划 | 按事件时间设置有效期（TTL），到期不再作为当前计划使用 |
| 何时失效不确定，如持续中的目标 | 设置复核时间，届时确认是否仍适用 |
| 稳定偏好、重要事实或历史经验 | 不统一设过期时间，按新证据更新并保留适用条件 |

有效期由业务决定，没有通用的天数。起步可采用 **「按需设有效期 + 定期去重 + 用户修改或删除」**。

## 没有有效期，怎么遗忘？

先去重、合并和清理已被替代的信息；出现检索噪声或容量压力后，再结合重要性、最近有效使用时间和频率，选择降权或归档。**「长期未使用」不能单独作为删除重要事实的依据**，被召回也不等于有效使用。

- 降权：仍可检索，但优先级降低。
- 失效或归档：退出当前事实或常规检索，按需保留历史、支持恢复。
- 删除：移除记忆及对应索引、缓存；用户明确要求删除时直接处理，不能用归档代替。

清理后通过[[agent-memory-evaluation|跨会话评测]]检查：旧记忆是否停止生效，仍有价值的信息是否被误删。

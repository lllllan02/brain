**对话历史存储是按会话保留用户消息、模型回复、工具调用与结果，让后续交互和原文回查有记录可用。** 进程内的消息列表只能延续当前运行；需要关闭后继续对话，就要把记录持久保存。

[[agent-context|上下文管理]]决定本轮模型看到什么，历史存储决定哪些记录仍然可用。两者分开，才能在缩减输入时保留可追溯的原文。

## 存什么，存成什么样？

**保存结构化交互记录，Markdown 可用于阅读导出。** 接续对话需要保留以下信息，字段名称随框架和接口变化。

| 内容 | 保存目的 |
| --- | --- |
| 会话 ID、消息 ID 与消息顺序 | 找到会话，并按顺序读取交互记录 |
| 角色、内容类型与原始内容块 | 区分用户、模型和工具，保留文本、图片或文件信息 |
| 工具名称、参数、调用 ID 与返回内容 | 知道调用了什么，并把结果关联回对应调用 |
| 摘要、覆盖范围等上下文处理记录 | 判断哪些原文已被摘要替代，避免重复或遗漏 |

例如一个会话保存为 `session_01.jsonl`，每行是一个独立 JSON 对象。下面用简化字段展示一轮交互，不是某个模型 API 的固定格式：

```jsonl
{"id":"m1","role":"user","content":"检查服务为什么超时"}
{"id":"m2","role":"assistant","tool_calls":[{"id":"c1","name":"read_file","arguments":{"path":"/logs/app.log"}}]}
{"id":"m3","role":"tool","tool_call_id":"c1","content":"请求耗时 30 秒，超时"}
{"id":"m4","role":"assistant","content":"日志显示请求在 30 秒后超时"}
```

四行依次是用户消息、模型工具调用、工具结果和模型回复。`m1`～`m4` 标识消息，`c1` 将调用与结果配对；只保存 `c1` 无法恢复结果正文。此例由文件名区分会话，行顺序表示消息顺序。

大结果或附件若只保存引用，还要保证引用内容可访问。

[[pi-session-storage-summary|Pi 的会话文件]]用 JSONL 按行保存不同类型的条目，消息只是其中一种；会话元数据和配置记录也可以保存，但不必都进入模型输入。

## 怎样保存？

可以自行保存，也可以使用服务端提供的会话存储：

| 方式 | 怎样使用与取舍 |
| --- | --- |
| 本地文件 | JSON 可保存消息列表，JSONL 便于逐条追加；适合本地会话，需处理写入中断和并发 |
| 数据库 | 按会话与消息顺序保存，便于查询和事务管理；根据部署和并发需求选择 SQLite 等后端 |
| 托管会话 | 应用保存服务端会话 ID，通过接口追加和读取；需遵循服务的保留与删除规则 |

[[openai-conversation-storage-summary|OpenAI Conversations]]通过会话 ID 管理托管历史。自行保存时，格式与位置是两项选择：JSON 既可写入文件，也可存入数据库。

新消息和工具结果应随交互及时保存；写入重试时，根据记录 ID 等信息避免重复追加。

## 怎样读回上下文？

**按会话读取历史 → 选择本轮需要的消息 → 组装模型输入。**

采用压缩时，按[[context-compaction-storage|摘要覆盖范围]]接上保留原文；分页读取则要区分「只读了一页」和「历史已读完」。

[[anthropic-managed-agents-summary|Managed Agents 将会话日志与模型窗口分开]]，说明原始记录可以持续保存，而每轮只使用其中一部分。省略的内容可[[context-loading|按需回查]]，读取已有工具结果不代表重新执行工具。

历史回答「发生过什么」；[[agent-task-state|任务状态]]与[[agent-checkpoint-recovery|中断恢复]]还要处理当前进度和执行位置，不由保存消息自动解决。

## 前端已经显示一条消息，后端重启后为什么找不到？

流式片段可能先发给前端，完整响应尚未持久化；工具也可能已执行，结果还没写入历史。若界面把“已经显示”当作“已经可靠保存”，断线恢复时就会出现重复回复或缺失结果。

明确接收、持久化和展示的顺序，用稳定消息身份区分重传与新消息，记录生成中、完整、失败等状态。恢复时从已提交记录继续，未完成片段不能当作完整工具调用执行。若产品允许先展示再保存，应有明确的未完成状态与失败提示。

历史存储还要和业务状态分工：消息里说“退款成功”不构成账本证据，历史缺一条成功回复也不意味着需要重新退款。排障时同时核对消息记录、运行状态和外部回执，不能只修补聊天文本。

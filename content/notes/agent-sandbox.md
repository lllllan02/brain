**沙箱（Sandbox）是一种受限制的执行环境，通过技术机制隔离或约束其中运行的程序。** 在 Agent 中，通常是工具启动的命令、脚本或程序进入沙箱，模型本身不一定在其中运行。

主要防范三类问题：

- 泄露：越权读取数据，或把数据传给不该接收的对象；需要限制读取范围和传出渠道。
- 破坏：误改、删除数据，或干扰其他进程与系统；需要限制修改权限和影响范围。
- 耗尽：过度占用 CPU、内存、磁盘等资源；需要设置单个沙箱的配额和运行时限，并通过[[sandbox-concurrency|并发限制]]控制多个沙箱的总消耗。

这些限制由执行环境强制落实。[[sandbox-authorization|调用前的权限检查]]不能代替程序运行中的约束；获准修改的文件仍可能被改错，结果正确性还需要测试或审查。

沙箱可以通过本机权限机制、容器或虚拟机等方式实现，不要求虚拟出一台完整机器。[隔离机制参考](https://gvisor.dev/docs/architecture_guide/intro/)

[[docker-sandbox|Docker 的挂载、网络与配额配置]]展示了限制如何生效；接入 Agent 时，[[sandbox-lifecycle|隔离单位与生命周期]]决定不同调用是否共享状态。沙箱外的工具需要另行约束，允许读取的数据也需要经过[[tool-calling-harness|工具结果回传控制]]才能对用户公开。

**Agent 意图识别（Intent Recognition）是把用户表达转换成程序可以继续处理的任务描述。** 例如「查一下订单 A 能不能退」，需要得到「查询退款资格」这个任务类型和「订单 A」这个对象，再把它们交给对应的查询流程。

识别器本身可以是规则、训练过的文本分类器，也可以是 LLM。它们读取文字并产生标签或结构化结果；程序依据结果选择处理流程，补齐必要信息，再执行工具。下面用订单退款场景说明这些部分怎样连接，例子是教学示意。

## 最基本的识别怎样做？

先由开发者定义系统支持的任务，例如「解释退款规则」「查询订单退款资格」「提交退款」。这些任务名就是意图标签；「退款」本身太宽，无法决定该回答说明还是修改订单。

最简单的规则可以把明确的固定句式映射到标签。要识别更多说法，可以收集「用户句子 → 正确标签」样本，把句子转成数字特征，训练一个根据特征给各标签打分的分类器。新句子沿用同一转换，再取得候选标签。[[intent-classification|传统意图分类怎样从样本得到预测]]具体展开规则、词袋表示、训练和推理；编码器与向量匹配路线尚待展开。

另一条路径是给已经训练好的 LLM 提供任务定义、正反示例、当前消息和输出格式，让它直接生成理解结果。例如输出 `{"intent":"refund_eligibility","order_id":"A"}`，程序再解析和校验。[[intent-llm|用 LLM 识别意图并接入程序]]展示完整提示、JSON 和接收结果的处理逻辑。

两条路线都可以服务固定标签分类；使用 LLM 不意味着必须取消标签，也不意味着每次请求都要重新训练模型。是否采用独立识别调用，取决于是否需要复用、检验和路由这一中间结果。

## 识别后怎样完成一轮处理？

以「查一下订单 A 能不能退」为例：

| 环节 | 具体输入与输出 |
| --- | --- |
| 理解任务 | 从整句话判断为「查询退款资格」，不是「提交退款」 |
| 提取参数 | 从原文取出订单号 A，放入查询需要的字段 |
| 校验与选择流程 | 程序检查任务是否支持、订单号是否齐全，再进入退款资格查询 |
| 调用与反馈 | 在权限范围内查询业务系统，根据实际结果回答能否退款 |

**「识别」确定要做什么，「路由」选择处理流程，「工具调用」执行具体接口。** [[anthropic-effective-agents-summary#什么时候适合先路由？|路由模式]]适合类别清楚且分开处理有收益的任务。开放 Agent 也可以在一次模型决策中提出工具调用，再由程序执行；这不要求额外部署一个专门的「意图 Agent」。[[tool-calling|工具调用]]格式正确仍不能证明用户意图理解正确，权限和业务限制由[[agent-guardrails|行为约束]]检查。

## 下一句话怎样接上前面的任务？

用户先说「帮我查能不能退」，再补「订单 A」，第二句只给了参数。系统需要保留前一轮任务，将 A 补进去；如果用户改口「换成订单 B，只查别退」，则需要更新对象并保留查询范围。

这涉及实体提取、槽位填充和对话状态：实体是从文字中识别出的对象，槽位是任务需要填写的字段，状态记录跨轮仍有效的任务与字段值。[[intent-dialogue-state|参数提取与多轮意图更新]]用逐轮输入和状态变化解释怎样抽取、合并与校验，而长期运行中的进度和结果由[[agent-task-state|任务状态管理]]继续维护。

一句话也可能包含多个要求，如「查退款资格并解释手续费」。识别时保留这些目标，再交给[[agent-planning|规划]]安排依赖与顺序，不能为了输出单标签而丢掉其中一个。

**待展开：** 多目标与条件请求目前只交代了边界和状态示意；LLM 分支标明了输出结构与程序处理的缺口，尚不能把单任务示例直接用于这类请求。

## 信息不足时怎样继续？

「订单 A 帮我处理一下」缺动作含义，「帮我查能不能退」缺订单号，「订单是否已经发货」则缺业务事实。三种情况分别需要澄清任务、补齐参数或查询系统；系统不支持的需求应进入回退路径。

[[intent-clarification|意图不确定时怎样澄清与回退]]展开候选分数检查、具体追问、回答合并与停止条件。澄清后的结果仍需校验，模型自报的高置信度不能代替有效授权。

## 怎样知道这条链路做对了？

用未参与开发的请求检查「任务标签、对象、约束和最终动作」是否符合预期，并加入同义表达、否定、撤回、跨轮指代、多目标与不支持的请求。标签准确率衡量分类，字段正确率检查提取，完整任务结果检查系统是否做对事情；这些指标不能相互替代。

在[[agent-evaluation|Agent 评测]]中还应记录错误执行、无必要追问及澄清后的改善。文中的样本、提示与流程用于理解机制，未作为本地完整服务验证。

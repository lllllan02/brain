**Agent 的按需加载，是根据当前任务需要，逐步提供资料、指令或工具定义的组织方式。** 这些内容全部预先带入会占用窗口，也会增加无关信息；先提供必要线索，再展开细节，可以让每轮输入更聚焦。

## 哪些内容可以按需加载？

| 加载对象 | 先提供什么 | 需要时再加载什么 |
| --- | --- | --- |
| **历史消息** | 当前任务状态、旧历史摘要与存档入口 | 被摘要省略的原始约定、决策过程或证据 |
| **工具结果** | 执行状态、简短预览与结果位置 | 日志、查询结果、长页面中的相关片段 |
| **文档与代码** | 目录、文件名、搜索入口或命中片段 | 当前问题涉及的章节、函数和上下游代码 |
| **长期记忆** | 当前任务与用户标识等查询条件，必要的核心偏好 | 相关的历史经验、偏好和事实 |
| **工具定义** | 少量常驻工具和工具发现入口 | 匹配工具的用途说明、参数 Schema 等完整定义 |
| **Skill 指令与资源** | Skill 名称、描述和适用场景 | 对应操作说明，以及用到的附属文档、模板或脚本 |

前三类属于[[context-loading|任务资料的按需获取]]，包括原文回查和局部读取；知识库中的材料也可以通过 [[rag|RAG]] 检索后提供。[[agent-memory-retrieval|长期记忆检索]]还要判断记录是否适用于当前用户、是否仍然有效。

[[tool-loading|工具按需加载]]决定模型本轮知道哪些工具、怎样传参；读取工具结果则是在获取已经执行过的内容，两者应分开管理。Skill 提供完成任务的方法：[Anthropic 的渐进式披露设计](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)先展示名称与描述，匹配任务后读取 `SKILL.md`，再按需要读取附属资料。执行脚本也不一定要把脚本源码放入模型窗口。

## 共同点与边界

这些做法都可以按「**发现入口 → 判断需要 → 获取必要内容 → 继续任务**」理解。判断可以由程序规则完成，也可以由模型发起搜索或读取；已知位置时直接读取，不必都经过向量检索。

加载后的用途不同：资料提供证据，Skill 提供方法，工具定义描述可调用能力。它们能共用按需提供的思路，但不能因此混成一种检索对象或统一协议。

按需加载会增加查找和等待，也可能漏掉重要内容。核心目标、必要约束与发现入口应保持可见；新取回的内容仍需受[[context-budget|上下文预算]]约束。这里减少的是模型本轮看到的内容，原始存储量不一定减少。

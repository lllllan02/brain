**人工介入（HITL）是在 Agent 执行过程中，将部分决策、审核或操作交给人参与的机制。** 自动权限校验属于[[agent-guardrails|行为约束]]；等待人确认或判断才属于人工介入。

## 为什么需要？

重要操作需要人承担决定，关键信息可能只有用户知道，阶段产物也可能需要专业审核。此时继续自主执行可能造成错误或返工，需要让人决定是否继续、如何继续。

## 何时介入？

- **审批（Approval）**：执行删除、发送或发布等操作前，按权限与风险规则确认是否允许执行。
- **决策（Decision）**：信息缺失或存在重要选择时，请人补充或选择，例如考试日期影响学习计划。
- **审核（Review）**：阶段产物形成后，请人决定接受、修改还是重新执行。

这是常见职责划分，不是固定流程。审批和审核通常设在明确节点，决策更动态；三者都可以由程序规则触发，也可由模型提出请求。强制审批由 Runtime 保证，不能依赖模型主动询问。

## 如何暂停与恢复？

**触发介入 → 暂停相关执行 → 保存状态与待处理事项 → 展示问题或操作 → 接收人的决定 → 校验后继续、修改或终止。** Runtime 负责暂停与恢复，等待原因和待回答问题写入[[agent-task-state|任务状态]]，审批请求及决定另按具体操作记录；跨进程等待需要[[agent-checkpoint-recovery|持久化与检查点]]。[HITL 中断与恢复示例](https://docs.langchain.com/oss/python/langchain/human-in-the-loop)

[[openai-guardrails-summary|OpenAI SDK 的检查与审批]]展示调用 ID 关联、批准范围及可信状态恢复。

审批应对应具体操作与参数；参数变化后重新判断是否需审批。拒绝或未回复不能当作同意，恢复前仍须校验权限和操作条件。

工具需要越过[[agent-sandbox|沙箱]]默认边界时，可采用「暂停相关操作 → 申请具体额外权限 → 获准后按新边界执行」。沙箱负责拦截，Runtime 负责审批和权限调整。只有策略允许申请的权限才进入审批；明确禁止的操作直接拒绝，资源超限通常先终止，再判断是否调整额度。授权应限定到必要的操作、资源和有效范围。

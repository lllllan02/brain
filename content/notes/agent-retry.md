**Agent 重试是在失败后，按错误类型与预算重新执行调用或任务的容错机制。** 网络波动、暂时限流等故障可能自行恢复，有限重试可以让任务继续；参数或策略有问题则需要[[agent-self-correction|自我纠正]]，不能只重复原请求。

## 两个层级

- **操作级重试**：覆盖模型调用和工具调用。可在调用包装器或中间件中进行错误分类，对可恢复故障有限重试；耗尽后将错误交给上层，通常不需要 LLM 决策。
- **任务级重试与恢复**：步骤最终失败后，由 Runtime 或调度器决定从头重跑、依据[[agent-checkpoint-recovery|State / Checkpoint]]从可恢复节点继续，或终止、降级。恢复位置取决于已保存状态，不一定恰好是失败步骤。

## 怎么重试？

**分类错误 → 判断能否安全重试 → 退避等待 → 再次执行 → 超出预算则停止。** 对临时故障采用有上限的指数退避与随机抖动，遵循服务端等待提示，并限制次数、总耗时与费用。[退避与重试设计](https://aws.amazon.com/builders-library/timeouts-retries-and-backoff-with-jitter/)

可恢复的连接异常、暂时限流和部分服务端故障可以重试；配额耗尽、权限不足或参数错误通常需要另行处理，不能仅凭 429、5xx 或「超时」就自动重试。

## 执行边界

- **副作用**：超时不代表远端未执行；写操作需通过[[idempotency|幂等键、状态查询或去重]]避免重复，任务重跑也要核对已完成操作。
- **重试叠加**：SDK、中间件和任务层可能各自重试。明确各层职责并共用总预算，避免请求次数成倍放大。
- **结果**：重试保持原操作意图，但模型重新生成不保证输出相同；恢复执行也不自动保证外部操作只发生一次。

**Agent 重试是在模型调用、工具执行或任务步骤失败后，重新尝试相应操作的恢复机制。** 是否值得重试、是否安全和何时停止，统一遵循[[retry-decision|错误分类与重试决策]]。

## 重试什么，由谁处理

- 模型调用：连接中断或暂时服务故障，可由 SDK 或调用包装器重发；请求格式、上下文长度等问题需先修正请求。再次生成不保证与上次输出相同。
- 工具调用：暂时故障可由[[retry-wrapper|重试包装器]]有限重试；参数或工具选择错误则交给模型做[[agent-self-correction|自我纠正]]。程序重发与模型修改调用是不同动作。
- 任务恢复：步骤最终失败后，由 Runtime 或调度器决定停止、改方案或依据[[agent-checkpoint-recovery|State / Checkpoint]]从可恢复位置继续；不能默认整段任务可以安全重跑。

[[pydantic-retries-summary|Pydantic AI 的重试分层]]展示请求重发、工具修正和输出修正分别怎样计数，以及哪些重试对模型不可见。

## Agent 还要限制什么

模型轮数、工具修正次数与底层 SDK 重试次数可能使用不同计数，需共同约束总耗时、调用量和费用，不能把单工具预算当成整次任务预算。

重新生成工具调用或恢复任务，不会自动保证外部操作只发生一次。已经执行成功但尚未记录结果的步骤，仍需按通用安全原则核查，避免重复副作用。

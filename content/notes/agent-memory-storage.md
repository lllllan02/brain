**长期记忆的存储方式取决于规模、查询和维护需求，可从文件或数据库起步，按需增加向量索引。** 它保存[[agent-memory-extraction|提取后的信息]]，可以与[[agent-storage|完整历史记录]]共用存储，但管理逻辑不同。

| 方式 | 适合的需求 | 需要承担的工作 |
| --- | --- | --- |
| JSON、Markdown 文件 | 小规模、本地使用、人工查看 | 并发修改、检索、版本与一致性管理 |
| 关系型数据库 | 结构化查询、事务、精确更新与删除 | 语义检索需额外索引或扩展 |
| 向量检索系统 | 按语义召回事实或经验片段 | 嵌入生成、索引更新、权限过滤与额外运维 |

业务数据和向量索引可以分离，也可以由同一数据库及扩展提供；是否引入独立向量数据库应由需求决定。向量是检索表示，仍需关联原文、来源和有效状态。

以下是「用户偏好简短回答」的假设条目，字段不是统一标准：

```json
{
  "id": "mem_001",
  "user_id": "user_123",
  "type": "preference",
  "key": "response_length",
  "content": "用户偏好简短回答",
  "source": "conversation_001:message_012",
  "created_at": "2026-10-09",
  "updated_at": "2026-10-09"
}
```

可按需要增加适用范围、有效时间与版本等字段。不同事实独立成条便于定向召回、修改和删除，但应保留理解所需的条件；把信息拆得过碎也会失去关系。对字段稳定的小型用户档案，维护一个结构化对象也可行。

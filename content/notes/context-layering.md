**上下文分层（Context Layering）是按信息职责分类，再为各类信息制定保留与更新策略的管理方式。** 分层本身不减少 Token，它决定[[context-trimming|裁剪与筛选]]、[[context-compaction|压缩]]应怎样作用于不同信息。

一种可用的划分是：

| 信息层 | 管理方式 |
| --- | --- |
| 指令 | 保留当前有效的行为规则与约束，不机械保留所有历史 system 消息 |
| 任务状态 | 保护目标、用户关键约束与进度，随执行更新 |
| 对话历史 | 按需要保留近期交互，筛选或摘要旧历史 |
| 工具结果 | 根据任务依赖保留、摘要或移除，必要时保留原文入口 |

这是一种职责划分，不能直接等同于消息角色或重要性排序。用户消息中的关键要求可以提取为[[agent-state|任务状态]]；工具结果也可能是唯一证据，不能因为来自工具就一律降低优先级。

例如，用户早先提出「只修改指定文件」，后续已经进行了多轮工具调用：这条约束应作为当前任务状态继续保留，普通过程记录才随窗口裁剪。需要分别限制各层占用时，再结合[[context-budget|上下文预算]]。

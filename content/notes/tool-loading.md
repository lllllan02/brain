**工具按需加载是根据任务需要，才把相关工具的完整定义提供给模型的机制。** 加载的是用途说明、参数 Schema 等调用信息；工具本身已经在[[tool-registry|注册表]]接入，无需重新加载代码或注册函数。

工具多时，全部定义会占用上下文，也会增加选择干扰。可以先提供少量常用工具和发现入口，其余需要时再展开。这里处理的是「有哪些能力、怎样调用」，工具执行后的日志或文档则属于[[context-loading|结果与资料的按需读取]]。

## 谁决定加载哪些工具？

| 方式 | 选择与加载过程 |
| --- | --- |
| 程序筛选 | 调用模型前，按任务阶段、运行状态等规则选择工具；[[pydantic-toolsets-summary\|Pydantic AI 工具集]]支持每步按上下文过滤 |
| 模型搜索 | 模型描述需要的能力，搜索服务匹配目录，再由 API 或运行程序加载完整定义 |

两者可以配合：程序先限定候选范围，模型再搜索需要的工具。搜索可以按名称、关键词或语义匹配，不必使用向量数据库。

## 搜索后怎样变成可调用工具？

以查询订单物流为例：程序先提供部分工具，模型在执行中发现还需要物流查询能力，再通过搜索补充定义。

![[assets/tool-loading.png|工具按需加载时序：从完整目录筛选首批工具，模型按需搜索，加载匹配定义后再执行调用]]

**「搜索得到调用方式，执行才得到业务结果」。** [[claude-tool-search|Claude Tool Search]]返回的工具引用由 API 展开；[[openai-tool-search-summary|OpenAI 工具搜索]]则支持托管搜索和应用自行检索。自己接入普通工具调用接口时，需要由程序把检索到的定义装配到后续请求，不能只返回一个工具名。

已加载工具能否继续复用，取决于接口怎样保留定义或引用；按协议维护会话时，不一定每轮都要重新搜索。

## 有哪些代价与边界？

搜索增加一步交互，也可能漏选工具；工具少时可以全部提供，常用工具可保持加载。取舍要同时看上下文占用、选对工具的比例与总耗时。

延迟的是定义进入模型上下文的时机，完整目录仍可能需要随请求发送。初始暴露名称、描述还是工具分组，也因实现而异。

本轮没有暴露某个工具，不代表服务端禁止调用。[[fastmcp-visibility-summary|服务端可见性控制]]与模型侧加载处于不同层，执行时仍需落实权限校验。

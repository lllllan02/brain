**边界验证要确认任务能正常工作，也确认它确实越不过限制。** 只看到请求失败，可能是依赖没装、服务没启动或网络本身故障，并不能证明沙箱有效。

| 想验证什么 | 怎么做对照 |
| --- | --- |
| 文件边界 | 允许的文件能读写；保护文件不能读取或保持未修改 |
| 网络边界 | 先确认测试服务正常，再验证允许目标可达、禁止目标不可达 |
| 凭据保护 | 使用假密钥：获准请求认证成功，未授权目标不带密钥，输出不回显秘密 |
| 资源限制 | 用有界测试负载观察限额实际生效，不只看配置值存在 |
| 任务清理 | 启动可识别的子进程，取消或超时后确认后代与端口已释放 |

先检查配置生成，再启动真正受限的程序，最后验证审批、执行和清理的完整流程。这三层分别检查“规则写对了”“限制生效了”“系统串起来了”，不能互相代替。

[[codex-sandbox-tests|Codex 的边界测试]]提供具体例子。结论只覆盖实测的平台、配置和工具入口；缺依赖而跳过不算通过，一条 Shell 测试也不能证明文件工具或外部服务受到同样保护。以上是验证思路，未在此执行沙箱测试。

**生命周期决定任务之间共享什么，以及结束后哪些状态还会留下。** 每次创建全新环境更容易分开状态，但重复准备依赖有成本；一直复用则可能让文件、凭据或后台服务影响下一项任务。

| 任务需要什么 | 选择怎样的生命周期 |
| --- | --- |
| 独立的一次性命令 | 新建进程，执行后结束；如果使用同一目录，文件仍共享 |
| 同一任务连续修改、测试 | 多次调用复用任务工作环境，保留依赖与文件 |
| 持续交互或后台服务 | 保留进程会话和交互状态，明确所有者与结束条件 |
| 不同用户或不应互相影响的任务 | 使用分开的环境与数据范围，避免直接复用未清理状态 |

由[[agent-harness|Harness]]安排：**分配环境 → 执行调用 → 收集结果 → 暂停保留或清理回收**。暂停是保留状态，不是清空；恢复时仍要检查权限和凭据是否有效。

[[codex-exec-session|Codex 持续命令]]可跨多次工具调用存活；E2B 支持环境暂停恢复。[E2B 架构](https://github.com/e2b-dev/runtime/blob/main/docs/ARCHITECTURE.md)

隔离环境仍可能共享宿主可写目录；[[worktree-sandbox-usage|Worktree]]也只分开工作副本。删除容器不会撤销已修改的宿主文件或已发送的 API 请求。结束时先保存结果，完成[[sandbox-processes|子进程清理]]，再释放[[sandbox-concurrency|执行名额]]。

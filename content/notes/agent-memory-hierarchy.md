**分层记忆（Memory Hierarchy）是一种按需组织模型输入的机制：少量必要信息留在上下文，大量历史与细节保存在外部，需要时再取回。** 历史可以不断增长，每次推理能读取的内容却有限，因此要控制本轮输入的范围。

## 按本轮是否需要来分层

| 层次 | 放什么 | 怎样使用 |
| --- | --- | --- |
| 常驻信息 | 目标、约束、稳定偏好 | 每轮加载，保持简短有效 |
| 当前工作集 | 近期消息、当前证据、工具结果 | 随任务推进加入、替换或移出 |
| 外部记录 | 完整历史、日志、详细文档 | 通过读取或检索取回相关片段 |

分层依据是**「本轮是否需要直接看到」**，与短期／长期的作用域划分不同：长期偏好可以常驻，当前任务的大文件也可以外置。[[memgpt-memory|MemGPT]]用这类分工管理有限上下文；[[letta-memory|Letta 的常驻块与归档]]、[[claude-code-memory|Claude Code 的记忆索引与主题文件]]体现了类似思路，具体加载规则各不相同。

## 用摘要接续任务，用原文恢复细节

假设 Agent 排查测试失败：上下文保留目标、已排除的假设和下一步，完整日志放在外部。旧输出移出前，摘要留下**「任务进度与证据位置」**；后续需要某个错误字段时，再按位置读取日志片段。

[[anthropic-context-engineering-summary|上下文压缩与外置笔记]]因此可以配合：摘要减少持续输入，原文补回摘要省略的细节。摘要可能遗漏条件，原始记录的保留期限仍需按任务要求决定。

## 存得下，还要找得回

外部信息只有经过[[agent-memory-retrieval|检索与注入]]才会参与推理。取回的片段同样占用上下文，需要限制读取量、查询次数与耗时，并为输出和新工具结果预留空间。

**「外部存储扩大了可访问的信息量，却不保证模型会查、查对或恢复全部细节。」** 验证时可清空旧上下文，让 Agent 接续任务并回答摘要未包含的问题，检查它能否回查证据，而非凭空补全。

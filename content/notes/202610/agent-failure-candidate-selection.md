# Agent 线上 Trace 凭什么进入错例候选池？

依据**可观测的异常信号**判断哪些 Trace 值得检查，同时从未命中信号的流量中随机抽样。进入候选池只表示有失败嫌疑，尚未确认是错例。

1. **判断依据**：来自任务目标、行为约束和执行协议。用户信号包括点踩、纠正和转人工；执行信号包括工具报错、参数校验失败和重复调用；结果信号包括「回复成功，但业务状态未变化」；自动评审用规则或 LLM Judge 检查答非所问、缺少依据或违反行为要求。工具报错本身不能证明 Agent 处理错误。
2. **做法与工作**：把每个信号实现成可执行的检测规则或评分标准，记录命中理由、对应证据和规则版本；LLM Judge 用人工标注样本校准。合并同一 Trace 的多次命中，按严重程度、频率和业务影响安排审核；按任务类型随机抽样未命中流量，发现未知失败模式。
3. **产出**：带来源 Trace、触发信号、证据和审核优先级的候选记录；随机抽样记录注明抽样来源，不预先标成错误。用审核后的「确认错例数 / 已审核候选数」观察筛选有效性，随机抽查用于发现漏检模式。

例如「取消工具返回 timeout ＋ 回复宣称已取消」命中成功声明缺少执行依据。人工发现新的失败模式后，再补充检测规则；只依赖已知规则会遗漏没有明显异常的错误。
